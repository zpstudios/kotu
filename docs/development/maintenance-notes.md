# 개발 시 찾아보는 규칙

### 1.1 자료 보존과 작업 마무리 — 2026-11-17 사용자 확정

**보존 필요성이 있는 자료를 선별해 남긴다.** 사용자는 반드시 삭제해야 할 자료를 제외하고 전부 남기는 방식과, 불필요한 자료를 다른 폴더나 제외 규칙으로 옮겨 누적하는 방식을 원하지 않는다.

- **남길 자료**: 현재 제품·문서 정본, 고유한 사용자 작업과 미통합 변경, 중요한 결정·변경 이력, 재현이나 미해결 문제 판단에 필요한 증거, 사용자가 보존을 지정한 자료다. 기존 Git 이력과 정본에 충분한 내용은 여러 사본·장문의 로그로 중복 보관하지 않는다.
- **완료 시 정리**: 현재 작업에서 만든 중간 사본·일회성 검증 산출물·중복 원자료는 필요한 내용의 반영과 검증을 마친 뒤 역할이 끝났는지 판단해 정리한다. 사용자가 폐기한 대상을 새 백업·압축본·보관 폴더로 다시 남기지 않는다. 필요한 이력은 정본이나 Git에 간결하게 기록한다.
- **제외 규칙의 용도**: 빌드 출력·재사용 캐시·로컬 설정처럼 반복 생성되거나 작업에 필요한 비추적 자료에 쓴다. 오래된 복구 문서나 중간 작업 사본을 치우지 않기 위한 수단으로 추가하지 않는다. 캐시도 재사용 가치와 용량을 보고 관리한다.
- **범위와 보호**: 정리는 현재 작업이 만든 자료 또는 사용자가 지정한 대상에 한정한다. 기존 고유 자료·진행 중인 작업·사용자 설정·별도로 보호 중인 복구 보존본을 포괄 삭제하지 않는다. 미추적 또는 ignore 상태라는 사실만으로 불필요하다고 판단하지 않는다.
- **새 자료 생성 전**: 정본에 반영할 내용인지, 잠시 필요한 중간 자료인지 먼저 구분한다. 완료 보고에는 남긴 중요한 자료와 정리 결과를 알리며, 모든 작업마다 별도 보관 폴더·목록·보고서를 늘리지 않는다.

## 문서 완료·인계 정리 절차

모든 작업의 완료·커밋·인계 전에 적용하는 정본이다. 매번 작업별 보고서나 보관 사본을 만들지 않는다. 기능의 커버리지가 늘면 해당 정본·열린 항목·결과 색인은 늘 수 있지만 지난 상태와 같은 설명을 쌓아 늘리지 않는다.

1. **현재 상태를 덮어쓴다.** HANDOVER는 최신 공식 제품·설치 판정, 근거·보호 백업 위치, 선택된 진행 작업과 바로 다음 행동만 남긴다. 릴리스 연대기·종료된 다음 작업·시험 일화를 제거한다. 이전 결과의 고유 정보는 아래 정본이나 고정 Git 원문으로 먼저 연결한다.
2. **A번호와 상태를 옮긴다.** 새 요구는 마지막 번호를 증가시키고 결과 색인에 한 번 등록한다. 열린 항목의 색인은 `열림`과 REQUIREMENTS 링크만 유지한다. 열린 표의 상태는 `진행`, `검토 대기`, `미착수`, `부분`, `보류`, `조사`, `백로그` 중 하나이며 상세 범위는 옆 칸에 쓴다. 완료하면 열린 표에서 제거하고 색인의 같은 행을 결과 한 줄·기능 정본·근거 링크로 갱신한다. 기존 A앵커는 짧은 호환 링크를 남기거나 모든 참조를 갱신한다. 후보/B 결정의 상태나 미검증을 자동으로 완료하지 않는다.
3. **고유 정보의 목적지를 대조한다.** 사용자 원요구·정정·철회, 유효 결정/이유, 실패/재현, 관측과 추론의 구분, 보류/남은 조건, 보호 경로를 변경 전과 비교한다. 지속 사양은 기존 기능 정본에, 현재 검증 경계·착수 조건은 DEVICE-CHECKS의 해당 행에 남긴다. 과거 수치·CI·복원 차이·취소 경과는 커밋 전체 ID와 실제 파일/행의 고정 링크로 회수되게 한다. 의미가 다른 기록을 중복으로 지우지 않는다. 흩어진 근거는 기존 공용 [근거 색인](../history/evidence-index.md)에서 연결하고 장문 원본을 다른 파일로 복사하지 않는다.
4. **자동 검사와 수동 검토를 나눈다.** `pwsh -File eng/Test-Documentation.ps1`, 검사 변경 때 `pwsh -File eng/Test-Documentation.Tests.ps1`, CI 변경 때 `pwsh -File eng/Test-ReleaseWorkflow.ps1`을 실행한다. 검사 결과와 Git diff에서 이동 목적지·기존 주소·한글·실제 상태를 확인한다. 자동 검사는 의미 보존·의미상 중복·원문 링크의 주장 일치·로컬 보호 자료 실존을 판정하지 못하므로 이 항목은 독립 검토에서 확인한다. 전체 해시/목록을 본문에 전사하지 않는다.
5. **남길 자료와 완료 범위를 확정한다.** 위 자료 보존 기준으로 이번 작업의 중간 사본·일회성 산출물만 정리한다. 고유 자료·사용자 설정·보호 백업은 수정하지 않는다. 로컬 검증·커밋/푸시·배포·설치 중 실제 끝난 범위만 보고하고, 남은 단계는 HANDOVER의 다음 행동에 남긴다.

### 검사 계약과 성장 허용

[문서 검사](../../eng/Test-Documentation.ps1)는 명시된 현재 문서만 구조·중복 대상으로 삼는다. 긴 문단과 표의 각 데이터 행은 공백을 정규화해 같은 파일 안에서도 비교하며 완전 일치만 실패시킨다. 과거 문서·버전별 변경 설명을 의미 중복 검사에 넣지 않는다. 링크는 Git 추적 문서와 새 docs 문서를 검사하되 사용자 `.codex/`를 열거나 순회하지 않는다.

HANDOVER는 두 절·최대 10개 항목·한 항목 650자·총 4,000자로 현재 상태 역할을 제한한다. 열린 요구와 검수 표는 항목 수를 고정하지 않고 각 행 900자로 요약을 유지한다. 결과 색인은 A번호 연속·유일 등록과 열린 표 상호 연결을 검사한다. REQUIREMENTS 50,000자·DEVICE-CHECKS 20,000자는 최후 경보다. 실제 범위 증가로 경보를 넘으면 먼저 상세의 정본·요약/링크 배치를 검토하고 필요한 계약 변경과 이유를 함께 검토한다. 기존 중복을 통과시키기 위해 한도만 늘리지 않는다. 고정 Git 링크는 전체 이력이 있는 체크아웃에서 커밋·파일·행 범위도 검사하며, 얕은 체크아웃에서 조회할 수 없는 이력은 미검사로 표시한다.

## 5. 브랜딩·식별자 (불가침 규칙 포함)

  이름 이력: WinUtil(초기 코드명) → ZP(v0.33.0) → KOTU(v0.86.0~). 당시 로컬 폴더명은 `winutil`이었다.

  `WinUtil-Main`·`ZP-Main`을 언급하는 주석. 리브랜딩 스캔은 **모든 과거 이름**으로 할 것.

  `AssemblyName`, 아이콘 접두사(`kotu-*.ico`)+생성 스크립트, Velopack packId, release.yml mainExe.

  배포물·저장소·문서 어디에도 쓰지 않는다**(이 파일 포함). 커밋은 저장소 로컬 config identity
  그대로 — `-c user.name=...` 일회성 오버라이드 금지. 표기 변경 시 4곳 동기:
  `Directory.Build.props`·LICENSE·release.yml packAuthors·site 푸터.
- csproj 등 XML 주석에 하이픈 2개(`--`) 연속 금지 — MSB4025로 빌드가 깨진다(실제 사례 있음).

## 3. 반드시 알아야 할 함정

### 3.1 레거시 식별자 — 절대 일괄 치환하지 말 것
이름이 세 번 바뀌었다: `WinUtil`(초기 코드명) → `ZP`(v0.33.0) → `KOTU`(v0.86.0~).
**구 이름을 그대로 둬야 하는 곳**이 있다. 바꾸면 "구 등록 청소" 로직이 깨진다:

- `ExplorerIntegration.LegacyBrands = ["ZP", "WinUtil"]`
- `%AppData%\ZP`·`%AppData%\WinUtil`·`ZP-Main`·`WinUtil-Main`을 언급하는 주석
- `release.yml`의 구 packId 안내 문구

**교훈**: A46에서 "ZP" 문자열만 훑어 `%TEMP%\WinUtil\subtitles`를 놓쳤다(A64에서 발견).
리브랜딩 스캔은 **현재 이름이 아니라 모든 과거 이름으로** 해야 한다.

### 3.2 셸 등록은 "등록한 그 순간"으로 굳는다
`ExplorerIntegration`이 레지스트리에 쓰는 값 중 **exe 절대 경로와 표시 문구는 재등록될 때만 갱신**된다.
- 그래서 A52로 모듈명을 바꿔도 이미 켜 둔 사용자의 우클릭 메뉴는 옛 문구 그대로다.
- A64로 exe명이 바뀌면서 등록된 경로가 없는 파일을 가리키게 됐고, 실기기에서 실제로
  .png 더블클릭이 '어떤 앱으로 열까요' 팝업으로 빠졌다 → **v0.89.0의 A78이 자동 복구를 넣음**
  (매 실행 시 `ReRegisterIfExeMoved`가 경로 어긋남을 감지해 켜져 있는 등록만 조용히 재기록).
- **Capabilities와 UserChoice(A38)는 ProgID만 참조**해서 경로 변화의 영향을 받지 않는다.
- A38의 자체 검증(`VerifyUserChoice`)은 **우리 해시 알고리즘 기준의 자기일관성 검사**다 —
  Windows가 실제로 수용하는지는 열어 봐야 안다. OS가 알고리즘을 바꾸면 "전부 성공"으로 보이면서
  실제로는 전부 무효가 되는 맹점이 있다(§5 첫 항목의 의심 지점).

### 3.3 하드웨어 모듈은 거의 전부 static (프로세스 공유)
`HardwareModule`의 폴러·섹션 캐시·구독자 수·리프레시 주기가 모두 `static`이고,
센서 선택(A18)·주기(A29)도 프로세스 단위 설정 키다. **A42에서 의도한 설계**(드라이버 핸들·WMI 조회 공유)라
통째로 뒤집으면 안 된다. **A70(v0.131.0)이 그 분리선을 그었다** — 폴러·주기는 공유 유지, 선택(A18)·바
크기(A62)는 `HardwareInstanceState`(인스턴스 상태 + 전역 1벌 저장 깔때기)로 창별 분리. A60 3차의 창별
상태(피닝·순서·모드)는 **이 클래스에 필드를 얹는 방식**으로 간다(새 static을 만들지 말 것).

### 3.4 빌드를 실제로 깨뜨린 것들 (재발 방지)

- **(런타임 · CI 무관) A352 확정 원인 — UI 스레드에서 `StorageFile.*`/셸 API를 동기로 부르면 COM이 메시지 루프를 펌프해 XAML 작업이 재진입 실행되고 `Microsoft.UI.Xaml.dll` 0xC000027B(E_UNEXPECTED)로 죽는다**(WinUI 3 = STA · 덤프 46프레임으로 확정 · v0.349.0). 규칙 ① 셸 API는 워커 `Run`에서만 ② XAML 콜백(CCC·`RegisterUpdateCallback`·SizeChanged·Loaded) 안에서는 WinRT/COM 호출·비동기 발사 금지(`DispatcherQueue.TryEnqueue`로 미룬다). 아래 "레이아웃 사이클" 항목(v0.348.0)은 **오진**이었다 — 그 수리는 무해해 존치.

- **(런타임 · CI 무관) A352 레이아웃 사이클 failfast** — `ContainerContentChanging` 안에서 x:Bind OneWay 대상 뷰모델 속성을 동기 대입하면 항목이 수십 개일 때 프로세스가 `Microsoft.UI.Xaml.dll` 0xC000027B로 죽는다(관리 예외 없음 · startup-error.log 없음 · 트레이스에 마지막 줄만 남는다). 초판은 ItemsSource 대입 전, 갱신은 디스패처/await 뒤(v0.348.0).

- **v0.344.0 CS0234 `Microsoft.UI.Text.FontWeight`** — WinUI 3에서 `FontWeight` **구조체**는 `Windows.UI.Text.FontWeight`이고 `Microsoft.UI.Text`에는 `FontWeights` **상수 클래스**만 있다. `TextBlock.FontWeight`의 선언 타입을 따를 것(v0.344.1 수리).
- **csproj/XAML 주석 안에 하이픈 두 개(`--`)** → MSB4025로 빌드 실패. XML 주석 문법 제약.
  (A64에서 `--mainExe`를 주석에 적었다가 실제로 깨짐.)
- **PowerShell 백틱 줄바꿈 뒤에 주석** → continuation이 깨진다. 백틱은 그 줄의 마지막 문자여야 한다.
- `resources.pri` — unpackaged WinUI는 exe 옆의 **고정 이름 `resources.pri`** 만 찾는다.
  없으면 시작 시 `XamlParseException`으로 조용히 죽는다(v0.5.5~0.5.7에 실제로 겪음).
  `AssemblyName`을 바꾸면 `$(TargetName).pri` 폴백 이름도 따라 바뀌므로 `release.yml`을 같이 고쳐야 한다.
- **`FrameworkElement.Parent`를 "이미 추가했나" 가드로 쓰지 말 것** — 라이브 트리 부착 전
  (뷰 생성자 안)에는 `Children.Add` 뒤에도 Parent가 null이라, 같은 요소를 두 번 Add해
  `COMException 0x800F1000`으로 죽는다(v0.111.0/A62가 유발, v0.113.2에서 수정).
  중복 방지는 `Children.Contains`(또는 자체 플래그)로. 이것도 **CI·정적 검사로 못 잡는 부류**다.
- **XAML 요소를 다른 컨트롤로 옮겨 붙일 때(reparent)** 는 **반드시 옛 부모의 `Children`에서 먼저 제거**해야
  한다. 판정은 `Children.Contains`(위 항목과 같은 이유로 `Parent` 금지). 선례가 셋 있다 —
  `ImageViewerView.TakeBottomBar()`(v0.27.0), `ExplorerPane.DetachPathBar()`(A91/v0.115.0).
  ※ **x:Name 필드는 부모에서 떼어도 살아 있다**(`InitializeComponent`의 `Connect()`가 잡아 둔 참조).
  그래서 옮긴 요소의 이벤트 핸들러·코드비하인드 참조는 손댈 필요가 없다.
- **정적 이벤트 구독은 반드시 Unloaded에서 해제한다** — `CompositionTarget.Rendering`(A88/v0.114.0)처럼
  프레임워크 static 이벤트에 뷰 메서드를 걸면, 해제를 빠뜨렸을 때 **뷰와 그 창이 통째로 샌다**.
  이 저장소의 관용구는 `Loaded`에서 `-=` 후 `+=`(이중 구독 방지), `Unloaded`에서 `-=`다.
- **`ImplicitUsings`가 `System.IO`를 넣어 주므로 짧은 이름 `Path`는 `Microsoft.UI.Xaml.Shapes.Path`와
  모호해진다**(CS0104). **파일에 `using System.IO;`가 없다고 안심하지 말 것** — v0.310.0(A318)이
  `src/Shared/MediaIcons.cs`의 `new Path`로 실제로 깨졌고 v0.310.1에서 수리했다.
  WinUI 도형을 코드로 만들 때 `Path`는 **완전 수식**(`new Microsoft.UI.Xaml.Shapes.Path()`)하거나
  별칭(`using ShapePath = …`)을 쓴다. 같은 함정을 가진 이름이 더 있다(`System.IO.Path`·`Stream` 계열).
  **암시적 using은 소스에 안 보이므로 정적 자체 검사가 못 잡는 부류**다 — 판정은 소스가 아니라
  `Directory.Build.props`/csproj의 `ImplicitUsings` 설정에서 시작할 것.
- **`{StaticResource Default*Style}` BasedOn 참조는 런타임에만 터진다** — v0.107.0의
  `DefaultDropDownButtonStyle`이 실기기 시작 크래시를 냈다(v0.113.1에서 수정). WinAppSDK 1.8이
  WinUI 컨트롤 기본 스타일을 지연 로딩해 App.xaml 파싱 시점에 키가 없다. **CI(컴파일)로는 못 잡고,
  정적 검사로도 못 잡는 부류** — 새 XAML에서 프레임워크 키를 StaticResource로 참조할 때는
  "그 키가 파싱 시점에 로드돼 있는가"를 의심할 것. 키 없이 setter만 둬도 기본 템플릿은 유지된다.

### 3.5 편집 도구가 한글 주석을 `\uXXXX`로 저장한다 (2026-08-24 실사고 · **2026-09-04 재발**)
파일 편집 도구가 한글 주석을 **유니코드 이스케이프 표기**(백슬래시 + `u` + `AC00` 같은 코드포인트 표기)로 저장해 버리는 사고가 있었다
(당시 구현 규칙에 이 검사가 추가됐다). ⚠️ **2026-09-04에 재발했고, 이번에는 서브에이전트가 아니라
오케스트레이터가 직접 편집하던 중**이었다(Opus 하위 에이전트 529 장애로 직접 구현하던 구간 — §2).
즉시 검출·복구했다.

- **검사 명령(커밋 전 상비)**:
  `grep -rnE '\\u(A[C-F]|[BCD][0-9A-F])[0-9A-F]{2}' <경로>` → **0건이어야 한다.**
- **복구 범위** = **한글 음절·자모·문장부호만** 실제 문자로 되살린다.
  ⚠️ **Segoe 글리프 리터럴(E7xx·E8xx 사용자 정의 영역)은 손대지 말 것** — 그것은 의도된 표기다
  (따옴표 안 글리프 리터럴도 오탐이 아니다).
- ⚠️ **오케스트레이터가 직접 편집할 때도 같은 검사를 돌린다** — 이 함정은 "서브에이전트의 문제"가
  아니라 **편집 도구의 문제**다. 위임 여부와 무관하게 커밋 전 grep이 관문이다.
