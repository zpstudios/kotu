# KOTU 공식 배포와 설치

### 3.1 제품 변경에서 이 PC 설치까지 — 2026-11-17 사용자 확정

사용자 지시: **"앞으로는 로컬 검증 후 커밋·푸시·공식 배포까지 마무리하고, 이 PC에는 그 공식 배포본만 설치하는 흐름으로 진행해 줘. 다음 세션에서도 지켜지도록 프로젝트 규칙에 명확히 기록해 둬."** 이전의 느슨한 '요청받으면 설치' 기준을 이 규칙으로 대체한다.

1. **로컬 검증**: 요청 범위의 변경을 구현하고 적절한 빌드·테스트·저장소 필수 검사를 통과시킨다. 로컬 실행본은 사전 검수용으로만 사용한다.
2. **커밋·푸시**: 제품 버전과 해당 버전의 변경 설명을 갱신하고, 요청한 변경만 건별 커밋한 뒤 즉시 push한다. 기존 승인 범위의 일상적인 커밋·push를 다시 허락받지 않는다. 복구 보관 자료와 무관한 변경은 포함하지 않는다.
3. **공식 배포 확인**: 해당 제품 커밋의 GitHub 빌드·릴리스 작업을 끝까지 확인한다. 실패하면 원인을 해결하고 필요한 검증을 다시 수행한다. 공개 태그·제품 커밋·릴리스 설명·설치 파일·업데이트 피드가 서로 맞는지 대조한다. 로컬 성공이나 push 성공을 공식 배포 성공으로 대신하지 않는다.
4. **공식 파일로만 설치**: GitHub에 게시된 그 버전의 공식 설치 파일을 내려받아 공개 해시를 확인한 뒤 이 PC에 설치한다. 로컬 publish/검수본을 실사용 설치 폴더에 직접 복사하거나 임시 버전으로 대체하지 않는다. 소스와 공식 배포, 이 PC 설치본을 별도의 제품 경로로 운영하지 않는다.
5. **보존·설치 검증**: 교체 전 설치 파일·설정을 백업하고, 열린 작업은 저장·정상 종료 후 진행한다. 사용 중이면 필요한 종료만 구체적으로 요청하고 강제 종료하지 않는다. 복구 보존본은 수정하지 않는다. 설치 후 버전·제품 커밋·공식 패키지와 설치 파일의 해시, 설정 보존·실행 상태·오류 기록을 확인한다. 설치 도우미의 정상적인 이름/위치 변경도 대응 경로의 해시로 검증한다.
6. **완료 보고**: 로컬 검증, 커밋·push, 공식 배포, 이 PC 공식 설치의 결과를 구분한다. 권한·외부 장애·사용 중인 앱 때문에 남은 단계가 있으면 그 범위와 이유를 밝히고 완료라고 표현하지 않는다. 공식 배포 링크·제품 커밋·검증 근거·백업 위치와 다음 세션에 필요한 상태를 기록한다.

**문서만 변경하는 경우**에는 현재 제품 버전으로 커밋·즉시 push하고 문서에 맞는 검사를 수행한다. 기존 공식 버전을 유지하며 새 제품 릴리스나 재설치를 만들지 않는다. 제품 코드가 함께 바뀌면 위 전체 절차를 적용한다.

### 테스트 Setup과 웹 업데이트 검수 (A418)

v0.428.0부터 작업 브랜치와 정식 배포 예행연습에서 만든 테스트 Setup은 `KOTU.Test`(표시명 **KOTU Test**)로 설치한다. 정식 설치본의 ID는 `KOTU`다. 과거 테스트 Setup은 정식판과 같은 ID를 사용했으므로 나란히 설치하는 검수에는 새 Setup을 쓴다.

정식 업데이트 수신을 검수할 때는 기존 정식판을 그대로 둔 채 테스트 Setup을 설치한다. 새 정식 릴리스가 공개되면 기존 정식판에서 **Settings → Updates**를 열어 버전을 확인하고 다운로드·재시작을 검수한다. 사용자가 직접 수신을 보려는 경우에는 먼저 정식 Setup을 실행하거나 업데이트를 대신 적용하지 않는다.

**컴퓨터 사용 사전 확인(2026-11-16 지시 유지)**: '컴퓨터 사용' 기능으로 앱 화면을 직접 확인하거나 조작하기 전에는 사용자에게 먼저 물어본다. 파일·빌드·프로세스 검증을 실제 화면 검수로 보고하지 않는다.
