# 릴리스 본문 관리

<a id="version-policy"></a>
## 버전 증가 기준 — A443

버전은 `major.minor.patch` 세 자리다. **1.0.0은 사용자가 공식 런칭을 선택할 때까지 보류**하고 그전에는 `0.x.y`를 유지한다. 작업 번호·커밋 수·작업량으로 버전을 올리지 않는다. 직전 공식 배포본과 비교한 사용자 동작의 차이를 기준으로 다음 표를 적용한다.

| 변경 종류 | 증가 규칙 | 예 |
|---|---|---|
| 새 기능·지원 형식·설정 추가, 사용 흐름이나 기본 동작의 의도적인 변경 | 가운데 `minor`를 1 올리고 `patch`를 0으로 초기화 | `0.439.3 → 0.440.0`. 시작 시 업데이트 안내 같은 새 기능 |
| 기존에 의도한 동작을 복구하는 버그 수정, 기존 동작을 유지하는 성능·안정성·보안·호환성 수리, 기능을 바꾸지 않는 표시·문구 보정 | 끝 `patch`만 1 올림 | `0.439.0 → 0.439.1`. 저장한 창 위치·크기 복원 수리 |
| 문서·검수 근거·개발 도구만 바뀌고 배포 제품은 바뀌지 않음 | 제품 버전 유지, 새 제품 릴리스·재설치 없음 | `0.439.0` 문서 커밋 |

한 배포에 여러 변경이 포함되면 기능·동작 변경이 하나라도 있을 때 minor를 올리고, 전부 기존 동작 수리라면 patch를 올린다. 내부 구조 변경이나 의존성 갱신도 사용자 동작이 유지되면 patch다. 기존 사용 방식·데이터 호환성을 바꾸는 경우에는 런칭 전이라도 minor로 분류하고 영향과 필요한 조치를 설명한다. 문서 전용 커밋은 현재 제품 버전을 유지한다. 이미 공개한 제품 자산은 바꿔치기하지 않으며 새 제품 릴리스에 번호를 재사용·역행하지 않는다.

제품 변경을 확정하기 전에 직전 공개 버전·변경 분류·선택한 다음 버전·이유를 작업의 검증 기록에 남기고 독립 검토에서 대조한다. 그다음 `Directory.Build.props`와 변경 설명을 함께 갱신한다. 자동 검사는 버전·설명문의 일치 여부를 확인하며, 기능 추가인지 버그 수정인지는 실제 요구·변경과 사람이 대조한다. 이 기준은 [자동 안내의 minor 조건](../features/product-contracts.md#automatic-updates)을 바꾸지 않는다. 같은 minor의 patch 업데이트도 Settings → Updates에서 확인·설치할 수 있다.

## 새 버전

1. 위 [버전 증가 기준](#version-policy)으로 버전을 선택하고 `Directory.Build.props`의 버전에 맞춰 `docs/RELEASE-vVERSION.md`를 작성한다. 첫 줄은 `# vVERSION` 또는 `# vVERSION — 제목`이어야 한다.
2. 직전 공개 릴리스와 실제 변경을 비교해 일반 사용자가 체감하는 변화나 필요한 조치만 적는다. 내부 검수용 빌드·설치 절차는 개발 문서에 기록한다. 이전 버전의 기능, 검수 결과와 한계를 이번 변경으로 잘못 소개하지 않는다.
3. `eng/Test-ReleaseNotes.ps1`과 `eng/Test-ReleaseWorkflow.ps1`을 실행한다. 버전 불일치, 누락, 빈 설명과 미완성 표시를 거부하지만, 설명의 의미가 코드와 일치하는지는 별도로 검토한다.
4. 배포 절차는 `eng/New-ReleaseBody.ps1`로 버전별 설명과 `eng/Release-Downloads.md`의 공통 다운로드 안내를 합쳐 `artifacts/release-body.md`를 생성한다. 공개 단계는 이 파일만 사용한다.
5. 배포 후 공개 본문을 다시 읽어 버전별 설명, 다운로드 링크와 실제 변경이 일치하는지 확인한다. 파일 업로드나 빌드 성공만으로 본문 검수를 대신하지 않는다.

일반 빌드에서도 설명문을 검사하므로, 버전만 올리고 노트를 빠뜨리면 실패한다. 이미 발행된 버전의 master 변경은 기존 릴리스 건너뛰기 규칙을 유지하며 자산을 다시 발행하지 않는다. 공통 다운로드 안내에 특정 과거 버전의 일회성 변경 공지를 넣지 않는다.

## 2026-11-08 소급 정정 기준

대상은 v0.36.1부터 v0.417.0까지 공개 릴리스 302개다. 기존 본문은 다섯 종류의 공통 안내문을 반복했고, v0.417.0에도 v0.86.0/v0.88.0 공지가 남아 있었다.

- 최근 다섯 버전(v0.413.0–v0.417.0)은 명시적인 버전별 설명문을 사용한다. v0.417.0의 실제 수정은 Preview 선택 타일의 테마 강조색 2px 테두리와 컨테이너 재사용 시 선택 표시 동기화다.
- 나머지 297개는 직전 공개 릴리스부터 해당 태그까지의 커밋 제목을 출처 링크와 함께 복원한다. 첫 공개 릴리스 v0.36.1은 앞선 확인 가능한 조상 태그 v0.35.1을 기준으로 삼는다. 공개 릴리스가 없는 중간 버전의 변경도 범위에 포함된다.
- 복원한 본문은 소급 작성 사실을 밝힌다. 당시 커밋 제목을 보존한 기록이며, 모든 과거 기능을 다시 실행해 검증했다는 뜻은 아니다.
- 다운로드 링크는 각 릴리스에 실제로 존재하는 자산에서 만든다. 버전별 문서의 상대 링크는 해당 제품 커밋을 가리키는 절대 링크로 바꾼다.
- v0.86.0과 v0.88.0의 실제 이름 변경 시점에만 당시 전환 안내 원문을 접힌 영역으로 보존한다.
- 공개 수정은 `body` 필드만 대상으로 한다. 원문을 먼저 백업하고 변경 전후 제목, 태그, 대상 커밋, 발행 시각, 자산 식별자·이름·크기·digest를 대조한다. 다른 편집이 감지되면 중단한다.

메인 검수의 원문 백업, 302개 후보, 개별 반영 기록과 최종 재조회 결과는 작업 사본의 `artifacts/release-notes-correction-20261108/main-review/`에 보존한다. `public-verification.json`과 `releases-after.json`이 전체 공개 반영의 대조 근거다. 이 정정은 앱 버전이나 기존 배포 파일을 변경하지 않는다.
