# 비동기 대기·재생 공통 정책 분리 — A360 (v0.357.0)

사용자가 승인한 구조 개선 5단계다. 기존 `codex/architecture-document-session`에서 진행하며
기본 브랜치 병합이나 정식 Release 발행을 포함하지 않는다. 1~4단계와 함께 계획된 경계를
정리하는 작업이며, 모든 UI와 네이티브 기능을 전면 재작성했다는 뜻은 아니다.

## 변경 경계

- `KOTU.Core.Threading.BoundedOperation`: 작업 완료와 시한·호출자 취소를 구분한다.
  작업 자체의 예외와 취소 토큰을 보존한다. 대기를 포기하면 취소 콜백을 한 번 시도하고,
  늦은 실패를 관측하며 늦은 성공 결과는 지정한 정리 콜백에 한 번 넘긴다.
  취소와 정리 콜백은 별도 작업으로 실행하므로 이 콜백의 지연이 원래 호출자의 대기를 늘리지 않는다.
  이미 완료된 작업은 호출자가 결과를 소유한다. 동시에 끝나는 경우 먼저 선택된 완료 경로만 소유한다.
- `ShellFetch`: WinRT 작업을 위 계약에 연결하는 어댑터. 기본 시한 5초와 동기 워커 호출을 유지한다.
  사용되지 않던 UI용 `WaitOrThrowAsync`를 제거했다. 기존 다른 호출부도 공통 대기 구현을 사용한다.
- `CancellableBatch`와 `ThumbnailExplorer`: 폴더 이동·재스캔·Unloaded 시 이전 배치를 취소한다.
  순번을 먼저 바꾼 뒤 취소하고 풀을 정리한다. 텍스트·썸네일 게이트 대기, 풀 큐와 워커 조회에
  토큰을 전달한다. 게이트는 실제 획득한 작업만 한 번 해제하며 재로드 뒤에도 같은 게이트를 쓴다.
  취소는 미리보기 없음 캐시나 시간 초과 횟수로 기록하지 않는다. 이전 디코드 실패의 UI 반영도 막는다.
  셸 작업 생성은 계속 워커 안에서 수행한다. 늦게 반환된 타일 썸네일은 Dispose한다.
- `KOTU.Core.Media`: 시간 표시와 재생 위치 저장 정책을 공통화한다. Audio/Video는 얇은 어댑터를
  사용한다. 모듈별 공개 `TimeText`, `PlaybackResumeStore`, `ResumeEntry` 이름을 유지한다.
  `audio.resume` / `video.resume` 및 JSON `Path`, `PositionMs`, `DurationMs`, `UpdatedAt`을 유지한다.
  구체적인 모듈 기록 형식으로 읽고 쓰므로 기존 설정 서비스의 타입 계약도 유지한다.
  30초·97% 경계, 경로 대소문자 무시, 기본 용량 300/최소 1, 보고 시 LRU 갱신과 내부 잠금을 유지한다.

## 정합성·회귀 검사

실제 공통 대기·배치·저장소를 호출하는 테스트를 추가했다. 완료/실패/원본 취소, 원본 TimeoutException,
시한과 호출자 취소 구분, 취소 콜백 실패·지연, 늦은 결과 해제 한 번, 늦은 실패, 게이트 대기 취소,
중복 해제 방어, Unloaded/재로드를 검사한다. 완료와 포기 경합에서 동기 정리의 지연을 피하도록
독립 검수에서 정리 전체를 별도 작업으로 보내는 수정을 반영했다.
기존 형식의 고정 JSON을 각 모듈로 읽고 다시 저장해 다른 모듈 키와 필드가 보존되는지 검사하며,
정확한 정책 경계와 LRU도 확인한다. 기존 시간 표시 테스트는 어댑터를 통해 공통 구현을 검증한다.

로컬 .NET SDK 8.0.424에서 전체 Release/x64 빌드가 경고 0·오류 0으로 성공했다.
8개 테스트 프로젝트 323건(기존 304 + 신규 19) 통과, 실패·건너뜀 0이다. Core 140건,
Audio 22건, Video 36건이며 나머지 기존 125건도 통과했다. 마지막 사전 취소/0초 시한 경합도
검사했다. 최종 TRX는 무시 대상 TestResults/phase5-final에 있다. 구조 검사 19개 프로젝트와
변경 diff 공백·한글 이스케이프 검사도 통과했다. 독립 검토의 발견 사항을 수정했다.
GitHub 설치 EXE·게시 없는 정식 배포 시험은 push 후 결과를 기록한다.

## 남는 한계와 실기기 확인

시한은 이미 생성된 비동기 작업의 대기에 적용된다. COM 작업 생성 자체, 동기 파일 읽기·복사,
협조하지 않는 네이티브 작업을 강제로 멈추지는 못한다. 영구히 응답하지 않는 네이티브 작업의
잔여 자원도 해제 완료를 보장하지 않는다. 늦은 정리는 타일 썸네일 소유권에 연결했으며 모든 기존
셸 결과의 자원 소유권이나 모든 탐색기 소비자의 배치 수명을 이번에 바꾸지는 않았다.
Audio/Video의 재생기, 장치 전환 잠금, 스왑체인, 네이티브 해제 순서는 기존 설계를 유지한다.

실기기 확인: 로컬·클라우드 폴더 사이를 빠르게 이동하고 뒤로 돌아왔을 때 타일 미리보기와 재시도가
정상인지, 창 닫기·재로드 후 미리보기가 이어지는지, 음악·영상 재시작 시 각자의 재생 위치가 유지되는지.
단위 테스트는 실제 WinUI 레이아웃·OneDrive COM 지연·libvlc 재생을 실행하지 않는다.
