# KOTU 요구사항 — 남은 작업 정리

> ※ 앱 이름은 v0.86.0(A46)에서 **ZP → KOTU (King Of The Util)** 로 변경 완료.
> 아래에 남은 "ZP" 표기는 변경 **이전** 이력을 가리키는 것이다.

> **운용 규칙**
> 1. "~~~ 구현/수정해줘" 요청은 이 문서에 항목 추가만 한다 (실개발 X).
> 2. 실제 개발은 "미반영 A?? 진행" 지시가 있을 때만 착수한다.
> 3. **A번호는 영구 ID** — 재정렬·재사용 금지. 완료되면 문서에서 항목을 제거하고 그 번호는 결번 처리. 신규 항목은 마지막 번호 다음을 부여.
> 4. **우선순위 정책 (2026-08-10 사용자 확정)**: **UI·코어 기능을 우선** 개발한다.
>    부가 기능군(녹화/녹음 A14·A15, HW 랭킹 A19, 포터블 배포 A43, HWP 뷰어 A45 등)은 후순위.
>
> 상태 표기:
> - `[미반영 An]` 아직 안 함 — 지시가 오면 착수 (부록 A 번호)

## 0. 브랜딩 · 명칭 (전역)

- ※ A46(**앱 이름 ZP → KOTU (King Of The Util)**, v0.86.0) 완료 — 결번. 확정·구현 내역:
  - **범위 = 표시명 + 시스템 등록 ID**(사용자 확정 2026-08-10). exe·어셈블리·솔루션·네임스페이스(`WinUtil.*`)는
    **초기 코드명 그대로 유지** — CI·설치 경로·업데이트 채널을 깨지 않기 위함.
  - 표시 문자열은 `Branding.AppName` 하나를 참조하도록 정리(창 제목·웰컴·설정 안내문·버전 표기·트레이 툴팁/메뉴·
    시작 실패 대화상자). 다음 리네이밍은 이 상수 + `ExplorerIntegration.Brand`만 바꾸면 된다.
  - `BrandName`: KOTU-image/-video/-audio/-doc/-zip/-info (※ `-zip`→`-archive`는 A52에서).
  - 시스템 ID 이전: ProgID `KOTU.*`(+확장자별 `KOTU.archive.zip`), Capabilities `Software\KOTU`,
    RegisteredApplications 값 `KOTU`, 셸 verb `KOTU.ExtractHere`·`KOTU.Compress`, AppInstance 키 `KOTU-Main`,
    `%TEMP%\KOTU`, 설정 `%AppData%\KOTU\settings.json`, 파일 아이콘 `kotu-*.ico`, Velopack packId `KOTU`.
  - **이관 없음**(사용자 확정): 구 `%AppData%\ZP` 설정을 복사하지 않는다(구 폴더는 그대로 남겨 되돌릴 수 있게).
    대신 구 브랜드(ZP·WinUtil) 레지스트리 등록은 **첫 실행 1회 자동 청소**
    (`ExplorerIntegration.CleanUpLegacyBrandRegistrations`, 플래그 `integration.legacyBrandCleanupDone`).
    `LegacyBrands` 배열에 구 이름을 쌓는 구조라 다음 리네이밍도 같은 방식으로 처리된다.
  - **UserChoice(A38) 재지정**: ProgID가 바뀌어 기존 기본 앱 지정은 무효 → 설정 화면 "n/m"이 0으로 떨어지고,
    연결 토글을 켜면 A38이 새 ProgID로 자동 재지정(실패 시 기존대로 A25 딥링크 폴백).
  - 앱 아이콘: 4글자 "KOTU"는 16px에서 뭉개져 중립 아이콘을 **"KO"/"TU" 2줄**로 확정(사용자 선택).
    모듈 아이콘 우하단 연결 표식은 `zp` → `kotu`(폰트 44→30).
  - 자동 업데이트 단절: packId 변경으로 구 ZP·WinUtil 설치본은 업데이트가 끊긴다 → 릴리스 본문에 수동 재설치 안내.
- ※ A52(**모듈 표시명 정리**, v0.87.0) 완료 — 결번. 확정 내역:
  `DisplayName` = **Image / Video / Audio / Document / Archive** (H/W Info는 현행 유지).
  v0.38.0 복수형·"ZIP" 지정과 v0.75.0 "Music" 확정을 대체. `BrandName`도 **KOTU-archive**로 일치.

  다음에 모듈명이 바뀌어도 문구가 자동으로 따라온다.
  ※ **알려진 한계**: 셸에 이미 등록된 verb 라벨·ProgID 설명은 **재등록될 때만** 갱신된다.

- ※ A64(**리브랜딩 2단계 — exe·어셈블리·프로젝트·네임스페이스 전면 rename**, v0.88.0) 완료 — 결번.
  A46의 "표시명 + 시스템 ID만" 결정을 대체. 확정·구현 내역:
  - **계기**: UAC 대화상자에 `WinUtil.App.exe`가 노출됐다. 핵심은 *"WinUtil이라는 단어가 나오는 것"* —

  - `AssemblyName` = **KOTU** → 산출물이 `KOTU.exe`. 프로젝트는 `KOTU.App`이지만 exe 이름은 `KOTU`다.
  - 디렉터리·프로젝트 파일·솔루션·네임스페이스 전부 `WinUtil.*` → `KOTU.*` (테스트 포함, `git mv`로 이력 보존).
  - **레거시 식별자는 의도적으로 보존**: `LegacyBrands = ["ZP", "WinUtil"]`(구 등록 청소용),
    `%AppData%\WinUtil`·`WinUtil-Main`을 가리키는 주석. 이들은 과거를 가리키는 값이라 바꾸면 안 된다.
  - 함께 고친 것: `release.yml`의 `--mainExe`(→ KOTU.exe)와 `$(TargetName).pri` 폴백(→ `KOTU.pri`),
    publish 경로, `build.yml`, README·ARCHITECTURE·BUILD, 저장소 URL(`zpstudios/zpro` → `zpstudios/kotu`).
  - **덤으로 발견해 고친 것**: 자막 임시 폴더가 아직 `%TEMP%\WinUtil\subtitles`였다
    (A46은 "ZP" 문자열만 훑어서 놓쳤다) → `%TEMP%\KOTU\subtitles`.
  - ※ **실기기 확인 필요**: 기존 설치본을 자동 업데이트했을 때 ① 시작 메뉴·작업표시줄 바로가기가
    새 `KOTU.exe`를 가리키는지 ② 설치 폴더에 구 `WinUtil.App.exe`가 남는지
    ③ 파일 연결(ProgID의 `shell\open\command`)이 새 exe 경로로 갱신되는지 —
    ③은 v0.88.0에서는 **연결 토글을 껐다 켜야 갱신**됐다(등록 시점의 `ExePath`를 굽기 때문).

- ※ A73(**리프레시 주기 목록 교체** — **50 / 200 / 500(기본) / 1000 / 2000 / 5000 ms**로
  A29(v0.84.0)의 100/300/1000·기본 300을 대체. `HardwareModule.RefreshChoices`·`DefaultRefreshMs`.
  구현 결정과 이유:
  ① **구값 이관 = "목록 밖이면 그보다 크거나 같은 가장 가까운 값으로 올린다"**(100→200, 300→500,
  v0.51.0 잔재 200→200, 목록 최대 초과는 5000). 기존의 "목록 밖이면 기본값으로 리셋"을 이 규칙으로 교체한
  이유는, 내림(예: 300→200)이면 사용자가 고른 적 없는 더 잦은 폴링이 되어 체감 부하가 갑자기 나빠지기
  때문이다. 이관은 `NormalizeRefreshMs`가 **읽을 때 1회 정규화 후 곧바로 되쓰기** 해서
  다음 실행부터는 그냥 통과한다(0·음수 저장값도 최단 50으로 올라가 폴러가 0 간격으로 도는 사고가 없다).
  ② **50ms 부하 경고 = 드롭다운 항목 툴팁** `Very frequent polling — higher CPU load`.
  항목 텍스트는 `50 ms` 그대로 두었다(숫자가 정보다). **상한 제한은 걸지 않는다** — 실측 부하는
  기기마다 달라 앱이 대신 판단할 근거가 없고, 확인은 사용자 몫이다.
  ③ 표기 폭: 가장 긴 `5000 ms`는 구 `1000 ms`와 **같은 7글자**라 2칸(84×40, A27) 버튼 폭 여유가 그대로다.
  ④ A51(맥박 창 = 주기 × 2)은 새 범위에서도 그대로 — 클램프 미추가(위 A51 항목의 재확인 메모 참조).
  ⑤ SMART(Storage) 조회는 A29에서 이미 **10초 시간 기반**이라 폴링 횟수와 무관 — 50ms(초당 20회)에서도
  SMART 부하는 10초에 1회로 동일함을 코드로 확인(`SensorService.StorageInterval`).
  ⑥ 부수 확인: 이력 링 600개는 50ms에서 30초치뿐이라 그래프 창(60초)보다 짧다 → A74에서 창을
  `min(60초, 링 용량 × 주기)`로 묶어 좌측 절반이 비지 않게 했다, v0.110.0) 완료 — 결번.
- ※ A74(**그래프 x·y축 스케일 표시** — 센서 그래프에 모서리 최소 표기로 축을 넣는다.
  **적용 대상 = A17 센서 그래프 셀 10개**(값을 그리는 그래프는 현재 이것뿐이다).
  **제외 대상과 이유**: ① **하단 바 전용 축약 표시** — A40으로 하단 바 두께가 44px에 1줄로 고정이라
  축 라벨을 얹을 세로 공간이 없다. 지금은 A17 셀이 그 자리에 살고 있어 같은 컨트롤이므로,
  "공간이 없으면 숨긴다"를 **폭 규칙(그래프 폭 90px 미만이면 라벨 숨김, A40의 좁은 폭 축약 관례와 동일)**
  으로 구현했다 — 좁은 창·카드 10개가 다 들어간 상태에서는 자동으로 사라진다.
  ② **맥박(EKG) 그래프(A29)** — 값이 아니라 스냅샷 **도착 타이밍**을 그리는 장식이라 y축이 존재하지 않는다.
  ※ **A60(그래프를 메인 좌측 정사각 셀로 이동)·A72(대형 그래프 모드)는 아직 미구현이라 대상이 아니다** —
  두 항목이 구현될 때 같은 `SensorCard` 렌더 경로를 쓰므로 이 표기를 그대로 물려받는다(대형 셀에서는
  폭 90px 규칙에 걸리지 않아 항상 보이게 된다). A71(하단 바 2개의 시간 스케일 차등)도 x 표기를 그대로 쓴다.
  구현 결정과 이유:
  ① **표기 방식 = 모서리 최소 표기**(눈금선·축선을 그리지 않는다 — 36px 높이의 작은 셀에 격자를 그리면
  그래프 자체가 안 읽힌다): 좌상단 = y 최대값 + 단위(`100°C`·`65W`·`100%`), 우하단 = x 시간 범위(`60s`),
  10px·`Opacity` 0.55, 그래프 선 위에 겹쳐 배치. **y 하한 0은 자명하므로 적지 않는다.**
  단위는 값 표기(`62 °C`)와 달리 **공백 없이** 붙인다(`SensorChannel.AxisUnit` 신설) — 좁은 셀에서 한 글자가 아깝다.
  ② **y 상한 규칙**: 백분율(%) = 0~100 **고정**(100%가 정의상 최대라 넘겨도 확장 안 함) /
  온도(℃) = 0~100 고정 + **초과 관측 시에만 10 단위 확장**(여기에 1·2·5 눈금을 쓰면 105℃ 한 번에
  축이 200℃가 되어 그래프가 바닥에 깔린다) / 그 외(W·RPM·MHz) = 관측 최대를 **1·2·5 × 10ⁿ 눈금으로 올림**.
  셋 다 **세션 중 단조 증가**(한 번 올라간 상한은 내려오지 않는다) — 값이 튈 때마다 그래프 전체가
  출렁이는 것을 막기 위해서다. 채널별(카드별)로 적용. 기존 A17의 "관찰 최대 ×1.1" 자동 스케일을 대체한다.
  ③ **x 범위는 계산값**(하드코딩 금지): 창 길이 = `min(60초, 이력 링 600개 × 리프레시 주기)`.
  A73의 50ms에서는 30초가 되고, 200ms 이상에서는 60초다. 주기를 바꾸면 **다음 스냅샷을 기다리지 않고**
  즉시 다시 그린다(`RerenderSparklines`, A51의 `RerenderPulse`와 같은 계열) — 5000ms에서 최대 5초 동안
  옛 표기가 남는 것을 막기 위해서다. 60초를 넘는 창은 분 표기(`3m`)로 떨어진다.
  ④ 값이 한 번도 없던 채널(권한 부족·미지원)은 축 라벨도 숨긴다 — 축만 떠 있으면 값이 있는 것처럼 보인다.
  ⑤ 렌더 수단은 기존과 동일(`Polyline`/`Polygon` 위에 `TextBlock` 2개를 같은 `Grid`에 겹침) —
  새 렌더링 스택을 들이지 않았다, v0.110.0) 완료 — 결번.

- ※ A61(**정보 모듈 Always on top → 하단 바만 표시** — A39의 핀을 켜면 메인 영역을 접어
  **타이틀바 + 하단 바 44px만 남는 얇은 상시 표시 바**가 되고, 끄면 접기 전 크기로 복원한다.

  모듈을 바꾸면 접힘도 함께 풀린다(펼 수단이 없는 납작한 창을 남기지 않는다 — A39와 같은 이유).
  ② **타이틀바는 유지**한다 — 드래그 이동·닫기 수단이고 인스턴스 번호 `[n]`(A56) 표기가 거기 있다.
  접힌 높이 = 비클라이언트(타이틀바 + 테두리) + 하단 바 44 DIP이며 **타이틀바 높이를 하드코딩하지 않는다**:
  `AppWindow.Size.Height − 클라이언트 높이(ScaleHost.ActualHeight × RasterizationScale)`로 실측한다
  (UI 배율 오버라이드(v0.24.0)가 걸리면 바도 실제로 그만큼 커지므로 그 배수를 함께 곱한다).
  ③ ⚠️ **A40 최소 창 크기(720×540 DIP)의 런타임 오버라이드가 필수** — `WindowMinSize`의
  `WM_GETMINMAXINFO` 하한이 540 DIP라 그대로 두면 접기가 통째로 무동작이 된다. 접힘 동안만 창별로
  최소 **높이**를 접힌 높이로 낮추고(`WindowMinSize.SetMinHeightOverride` — DIP로 들고 있어 모니터를
  옮겨도 DPI 환산이 옳다) 해제 시 540으로 되돌린다. **폭 하한 720은 접힘 중에도 유지** —
  하단 바가 그 폭을 전제로 축약 설계돼 있다(LayoutSensorCards·UpdateBarDensity).
  ※ **A40 수치를 만질 때 이 오버라이드를 같이 봐야 한다.**
  ④ **폭·위치는 접을 때 건드리지 않는다**(옮기지 않는다). 복원도 높이만 되돌리므로 접힌 채 폭을 바꿔도
  그 폭이 남는다. 최대화 상태에서 켜면 최대화된 창은 Resize가 먹지 않으므로 먼저 Restore한 뒤 접고,
  끄면 다시 최대화한다(되돌릴 높이는 A55가 추적해 둔 일반 높이).
  ⑤ **A55(창 크기·위치 저장)와의 상호작용 = 접힌 크기는 절대 저장하지 않는다**:
  `TrackNormalBounds`가 접힘 중에는 **높이만 동결**하고(폭·위치는 계속 추적해 접힌 채 옮겨도 반영),
  `SaveWindowBounds`에 접힘 분기를 더해 접힌 채 닫혀도 **접기 전 높이**가 저장된다.
  ⑥ **전체화면(⛶)과의 관계**: 접힌 채로 들어가지 않는다 — 먼저 펼치고 전환하며, 나오면 파생 상태
  재계산(`UpdateViewMode`)으로 (핀이 여전히 켜져 있으므로) 다시 접힌다.
  ⑦ **A69(최소화 → 트레이 숨김)·A68(인스턴스 색 테두리·번호)** 는 접힘과 무관하게 그대로 동작한다 —
  최소화 판정은 프레젠터 상태, 아이콘은 창 수명 기준이라 접힘이 끼어들 지점이 없다(코드로 확인).
  ⑧ 구조: 모듈 프로젝트는 셸을 참조할 수 없으므로(App → 모듈 단방향) **판단은 뷰, 실행은 셸**로 나눴다 —
  새 계약 `IWindowCollapseSource`(KOTU.Core.Contracts)로 뷰가 접기/펼치기를 요청하고
  `MainWindow.SetBarOnlyCollapsed`가 실제 창을 조작한다. 접기 요청은 지금 보이는 뷰의 것만 받고,
  펼치기는 뷰가 내려간 뒤(Unloaded)에도 받아준다.
  핀 툴팁도 새 동작에 맞춰 `Always on top (collapses to the bar)`로 갱신, v0.111.0) 완료 — 결번.
- ※ A62(**정보 모듈 하단 바 표시 크기 조절** — A61의 상시 표시 바에서 가독성을 확보하는 것이 목적.

## 8.1 All Readable 모듈 (신규)

- ※ A59(**All Readable 통합 모듈 신규** — 모든 지원 형식을 한 창에서 열어보는 모듈, v0.113.0) 완료 — 결번.
  파일을 열면 **센터와 하단 바만** 그 형식의 모듈 뷰로 교체되고(중첩 호스팅), 창·오버레이·시작 메뉴는
  계속 All Readable의 것이다. 확정·구현 내역:
  - ① **신규 프로젝트 `src/KOTU.Module.AllReadable`** — ID `allreadable`, 표시명 **`All Readable`**,
    브랜드명 `KOTU-all`(KOTU-doc·KOTU-info와 같은 축약 형식), 글리프 `E71D`(AllApps).

    자식 뷰는 셸이 넘긴 `IModule` 계약(`CreateView`)으로만 만든다.
  - ② **담당 확장자 = 자식 모듈 확장자의 합집합**. 그래서 좌측 리스트 오버레이(A57 ③의 주입 지점)와
    중앙 빈 상태 탐색기 필터가 자동으로 "전 모듈 지원 확장자"가 된다 — 오버레이는 자식이 바뀌어도
    **All Readable이 계속 소유**하고 필터도 그대로 합집합이다(모듈별 필터로 좁아지지 않는다).

    두고 단위 테스트했다(`AllReadableRoutingTests` 8건).

    합집합을 가진 이 모듈이 앞에 오면 탐색기 더블클릭이 전부 여기로 빨려 들어간다.
    자식 후보도 "등록된 모듈 − 자기 자신 − 확장자 0개(정보 모듈)"로 뽑아 **중첩 재귀를 원천 차단**했다.

    기존 6개 모듈은 기본 구현을 그대로 물려받아 코드 변경이 없다.
    같은 이유로 **파일 인자로 시작하는 경로(탐색기 더블클릭·연결 프로그램·드래그로 새 창)는
