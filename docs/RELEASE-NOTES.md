# 릴리스 본문 관리

## 새 버전

1. `Directory.Build.props`의 버전에 맞춰 `docs/RELEASE-vVERSION.md`를 작성한다. 첫 줄은 `# vVERSION` 또는 `# vVERSION — 제목`이어야 한다.
2. 직전 공개 릴리스와 실제 변경을 비교해 이번 버전의 수정 사항을 적는다. 이전 버전의 기능, 검수 결과와 한계를 이번 변경으로 잘못 소개하지 않는다.
3. `eng/Test-ReleaseNotes.ps1`과 `eng/Test-ReleaseWorkflow.ps1`을 실행한다. 버전 불일치, 누락, 빈 설명과 미완성 표시를 거부하지만, 설명의 의미가 코드와 일치하는지는 별도로 검토한다.
4. 배포 절차는 `eng/New-ReleaseBody.ps1`로 버전별 설명과 `eng/Release-Downloads.md`의 공통 다운로드 안내를 합쳐 `artifacts/release-body.md`를 생성한다. 공개 단계는 이 파일만 사용한다.
5. 배포 후 공개 본문을 다시 읽어 버전별 설명, 다운로드 링크와 실제 변경이 일치하는지 확인한다. 파일 업로드나 빌드 성공만으로 본문 검수를 대신하지 않는다.

일반 빌드에서도 설명문을 검사하므로, 버전만 올리고 노트를 빠뜨리면 실패한다. 이미 발행된 버전의 master 변경은 기존 릴리스 건너뛰기 규칙을 유지하며 자산을 다시 발행하지 않는다. 공통 다운로드 안내에 특정 과거 버전의 일회성 변경 공지를 넣지 않는다.

## 2026-11-08 소급 정정 기준

대상은 v0.36.1부터 v0.417.0까지 공개 릴리스 302개다. 기존 본문은 다섯 종류의 공통 안내문을 반복했고, v0.417.0에도 v0.86.0/v0.88.0 공지가 남아 있었다.

- 최근 다섯 버전(v0.413.0–v0.417.0)은 명시적인 버전별 설명문을 사용한다. v0.417.0의 실제 수정은 Preview 선택 타일의 테마 강조색 2px 테두리와 컨테이너 재사용 시 선택 표시 동기화다.
- 나머지 297개는 직전 공개 릴리스부터 해당 태그까지의 커밋 제목을 출처 링크와 함께 복원한다. 첫 공개 릴리스 v0.36.1은 앞선 확인 가능한 조상 태그 v0.35.1을 기준으로 삼는다. 공개 릴리스가 없는 중간 버전의 변경도 범위에 포함된다.
- 복원한 본문은 소급 작성 사실을 밝힌다. 당시 커밋 제목을 보존한 기록이며, 모든 과거 기능을 다시 실행해 검증했다는 뜻은 아니다.
- 다운로드 링크는 각 릴리스에 실제로 존재하는 자산에서 만든다. 버전별 문서의 상대 링크는 해당 제품 커밋을 가리키는 절대 링크로 바꾼다.
- v0.86.0과 v0.88.0의 실제 이름 변경 시점에만 당시 전환 안내 원문을 접힌 영역으로 보존한다.
- 공개 수정은 `body` 필드만 대상으로 한다. 원문을 먼저 백업하고 변경 전후 제목, 태그, 대상 커밋, 발행 시각, 자산 식별자·이름·크기·digest를 대조한다. 다른 편집이 감지되면 중단한다.

메인 검수의 원문 백업, 302개 후보, 개별 반영 기록과 최종 재조회 결과는 작업 사본의 `artifacts/release-notes-correction-20261108/main-review/`에 보존한다. `public-verification.json`과 `releases-after.json`이 전체 공개 반영의 대조 근거다. 이 정정은 앱 버전이나 기존 배포 파일을 변경하지 않는다.
