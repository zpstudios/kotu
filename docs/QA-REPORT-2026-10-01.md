## 3. 발견한 문제

### A378 — 손상 ZIP을 암호 파일로 오판하고 취소 후 로딩 상태가 남음

재현:

1. 일반 텍스트를 `invalid.zip`이라는 이름으로 저장한다.
2. Archive에서 파일을 연다.
3. `Password required` 대화상자가 뜨면 Cancel을 누른다.

실제 결과:

- 손상/비압축 파일인데 암호가 필요한 압축으로 안내된다.
- Cancel 뒤 제목은 `invalid.zip`을 연 상태로 남고 본문은 비어 있다.
- 하단 `Reading archive...`가 종료되지 않으며 해제 버튼은 비활성 상태로 남는다.

기대 결과:

- 암호화를 확실히 판별한 경우에만 암호를 요청한다.
- 그 밖의 손상·미지원 입력은 `Failed to open: ...` 같은 종료 가능한 오류로 표시한다.
- 암호 입력을 취소해도 진행 상태를 지우고 다시 파일을 열 수 있는 안정 상태로 돌아간다.

코드 대조:

- `SevenZipBackend.IsPasswordError`는 7-Zip 예외 문자열에 `password` 또는 `encrypted`가 있으면
  `ArchivePasswordException`으로 바꾼다.
- `ArchiveView.LoadArchiveAsync`는 이 예외를 받으면 암호 대화상자를 띄우고, 취소 시 상태 문구를
  정리하지 않은 채 반환한다. 실기기 결과와 같은 경로다.

### A379 — Mission Statement의 설정 저장 위치가 실제 동작과 다름

실제 화면에는 설정 파일이 `%APPDATA%\KOTU\settings.json`이라고 표시되지만, 같은 화면의 Mission
Statement는 모든 설정이 앱 옆 `settings.ini`에 있다고 말한다. 현재 정책과 맞는 한 가지 설명으로
통일해야 한다. 포터블 저장 방식으로 바꾸는 요구가 아니라 사용자에게 보이는 문구 정정이다.

## 4. 이번 실행에서 확인하지 않은 조합

아래 항목은 기능 부재 판정이 아니라, 장치·권한·외부 효과 또는 별도 대형 자료가 필요한 조합이라 이번
실행에서 값을 바꾸거나 끝까지 수행하지 않은 범위다.

- 인쇄 대화상자 이후의 실제 종이/PDF 출력
- 기본 오디오 입출력 장치 변경, 마이크, 화면 녹화/녹음
- 관리자 재시작, PawnIO 설치, 센서 드라이버별 값 정확도
- ZIP 외 7z/RAR/TAR 등 모든 형식, 암호가 실제로 걸린 정상 압축, 초대형/다중 압축, 압축 생성
- 모든 이미지 형식·애니메이션·EXIF 회전, 모든 미디어 코덱·자막·재생 장치
- 파일 연결·우클릭 메뉴 등록을 변경하는 시험, 설치 제거, 업데이트 롤백
- 트레이 종료, 미저장 문서 종료 확인, 접근 거부·읽기 전용·네트워크/클라우드 파일의 전체 조합
- 좁은 창/여러 모니터/모든 Windows 배율과 장시간 부하·메모리 누수 시험

이 조합들은 회귀 시험표나 전용 실기기 묶음으로 나눠야 재현성과 안전성을 유지할 수 있다.

## 5. 판정

v0.370.0에서 최근 수정한 Audio/Video 순서, 문서 빈 Fit 아이콘, PDF 기본 Contain 및 Fit width 정렬,
압축 해제 후 결과 폴더 자동 열기는 실제 설치본에서 정상 동작했다. 이번 표본에서 앱 중단은 없었고,
새로 확인한 수정 후보는 A378과 A379 두 건이다.
