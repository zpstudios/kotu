## 검수 기록을 사용할 때의 한계

- 이 대조는 문서·코드·기존 시험 정의를 읽은 결과다. 과거 시험 수·화면 관측을 이번 제품 시험 결과로 표현하지 않는다. 새 빌드·앱 실행·컴퓨터 사용은 수행하지 않았다.
- 과거 감시 계측의 `MaximumLive=2`, `MaximumNotifying=1`은 알림을 중단한 객체의 비동기 Dispose가 잠시 겹친 기록이다. 소유 세션 1개라는 계약을 ‘모든 순간 감시 객체가 물리적으로 1개’라는 관측으로 바꾸지 않는다.
- 캐시된 BMP의 순수 보기 왕복에서 추가 요청이 없었던 관측은 최초 미캐시 진입까지 보장하지 않는다. 앱 배율과 Windows DPI, 한글 문자열 입력과 실제 IME 조합, 같은 볼륨 기본 드래그와 보조키 드래그를 구분한다. 최종 수락 범위는 설계 정본의 ‘근거의 한계’를 따른다.
- 합성 가용성/권한 실패·취소 검수는 실제 클라우드 공급자나 모든 OS 경합의 증명이 아니다. 일부 구조 보고서 재구성, 첫 클립보드 복원 실패, 검수 중 설정 변경, 계측 기록 지연도 기존 정본의 한계를 유지한다.

## 초기 복구 안내의 후속 상태

`RECOVERY-NOTES.txt`의 ‘과거 Git 문서 2개·휴지통·버전 기록 미확인’은 초기 조사 시점의 기록이다. 저장소 밖 `%USERPROFILE%/KOTU-Recovery/2026-11-14/recycle-full-audit-20261114/RESULT.txt`의 2026-11-15 최종 보고를 읽어 다음 후속 결과를 확인했다. 이번에 클라우드를 다시 조회한 것은 아니다.

- 과거 HANDOVER/SESSION-LOG 원문은 각각 클라우드 버전 663.0/114.0으로 확보해 Git 객체와 대조했다. B의 547개 참조와 회수 Git 객체는 A의 `.git`과 섞지 않고 별도 저장소·bundle에 보존했다.
- 휴지통 KOTU 후보 전수 조사 후 중요 후보의 미확보·최종 읽기 실패는 0개로 정리됐다. 제품 경로와 다른 실험 버전·충돌도 별도 보존했다. 데이터 확보 완료와 모든 실험 코드의 제품 채택은 다른 판단이다.
- 최종 보고는 당시 OneDrive KOTU 정리 준비 완료를 판정했으며 삭제 실행 전 보고다. 그 문서만으로 삭제 실행이나 모든 과거 자료의 완전 복원을 주장하지 않는다. 이번 원문 정리는 OneDrive 추가 삭제나 휴지통 비우기를 포함하지 않는다.
- 최초 휴지통 전체 행 메타데이터의 유실, 생성 출력 editor.css의 복원 전 바이트 미확인, 조사 이전 영구 삭제 자료의 확인 불가 등 최종 보고의 한계도 유지한다.

현재 문서는 이 정리본을 참조한다. 원문을 폐기하기 전에 수행한 대조·해시 확인의 기존 기록은 `%USERPROFILE%/KOTU-Validation/20261117-recovered-docs-review/`에 있으며, 이번 폐기를 위해 원문 사본을 추가 보관하지 않았다. 자료 보존·정리 기준은 루트 AGENTS.md와 CLAUDE.md §1.1을 따른다.
