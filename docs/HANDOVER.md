# KOTU 인수인계 문서

> 세션이 바뀌어도 이어서 일할 수 있게 하는 문서. **이 문서 + `docs/REQUIREMENTS.md` 두 개면 충분**해야 한다.
> 저장소가 이미 기록하는 것(코드 구조는 `ARCHITECTURE.md`, 빌드는 `docs/BUILD.md`, 변경 이력은 git log)은
> 여기에 중복해 적지 않는다. 여기 적는 건 **코드를 읽어도 알 수 없는 것** — 결정의 배경, 함정, 대기 중인 확인.

> 최종 갱신: 2026-08-11 (v0.90.0 시점)

## 1. 지금 상태 한 줄

앱 이름 **KOTU (King Of The Util)**, 저장소 **zpstudios/kotu**, 실행 파일 **KOTU.exe**, 최신 **v0.90.0**.
저작 주체는 **ZP Studios**(A82/v0.90.0) — 개인 실명·개인 메일은 어디에도 쓰지 않는다. 커밋도 이 이름으로 남는다.
리브랜딩 2단계(A46 → A64) 후 실기기에서 **파일 더블클릭이 실제로 깨진 것이 확인**되어 A78(경로 자동 재등록)을 냈다.
**실기기 확인이 5개 버전치 밀려 있고**(§4), A38 관련 **미해결 관찰 2건**이 있다(§5 첫 항목).

## 2. 일하는 방식 (반드시 지킬 것)

1. **요청은 `docs/REQUIREMENTS.md`에 등재만 한다. 개발은 하지 않는다.**
   실제 개발은 사용자가 **"A?? 진행"** 이라고 지시할 때만 착수.
2. **A번호는 영구 ID** — 재정렬·재사용 금지. 완료하면 항목을 "※ 완료 — 결번"으로 바꾸고
   부록 A 표에서 행을 빼고, 결번 목록에 추가.
   ※ **미구현 항목의 내용이 바뀐 경우엔 새 번호를 주지 말고 그 자리에서 갱신**한다(A26·A40·A60이 그렇게 처리됨).
3. **커밋은 버전을 명기**한다: `v0.XX.0 [A??] 요약`. `Directory.Build.props`의 `<Version>`을 같이 올린다.
4. **push는 작업 묶음 끝에 1회.** master push만으로 CI가 태그·릴리스까지 자동 처리한다.
5. **개발 우선순위: UI·코어 기능 우선** (사용자 확정). 녹화/녹음(A14·A15), HW 랭킹(A19),
   포터블 배포(A43), HWP 뷰어(A45)는 후순위.
6. 세션 전환이 필요한 시점이면 **묻지 말고 이 문서를 갱신**한다.

### 검증 분업
- **Claude**: 코드 시뮬레이션으로 자체 검수 + CI 통과 확인까지.
- **사용자**: 실기기에서만 확인 가능한 것(레지스트리 반영, UAC, 트레이, 백신 반응 등)을 마일스톤 테스트로.
- 개발 환경에 **dotnet이 없다** — 로컬 빌드 불가. **CI가 유일한 컴파일러**다.
  그래서 push 전 정적 검사(네임스페이스·경로·XML 유효성 등)를 반드시 스스로 돌릴 것.

### 빌드·릴리스
- master에 push → `build.yml`(빌드+테스트)과 `release.yml`(publish+Velopack+태그+릴리스)이 동시에 돈다. 각 3~4분.
- CI 결과는 **Chrome MCP로 확인**한다. `github.com/zpstudios/kotu/actions/workflows/build.yml`에서
  최신 run의 `svg[aria-label]`을 읽으면 성공/실패를 알 수 있다.
- push는 remote 이름 **`zp`** (PAT가 URL에 박혀 있음). `git push zp master`.
- 샌드박스에서 git이 `.git/*.lock`을 못 지우는 경우가 잦다 → `rm -f .git/*.lock` 후 재시도.
  파일 삭제가 "Operation not permitted"면 `mcp__cowork__allow_cowork_file_delete`로 권한을 받는다.

## 3. 반드시 알아야 할 함정

### 3.1 레거시 식별자 — 절대 일괄 치환하지 말 것
이름이 세 번 바뀌었다: `WinUtil`(초기 코드명) → `ZP`(v0.33.0) → `KOTU`(v0.86.0~).
**구 이름을 그대로 둬야 하는 곳**이 있다. 바꾸면 "구 등록 청소" 로직이 깨진다:

- `ExplorerIntegration.LegacyBrands = ["ZP", "WinUtil"]`
- `%AppData%\ZP`·`%AppData%\WinUtil`·`ZP-Main`·`WinUtil-Main`을 언급하는 주석
- `release.yml`의 구 packId 안내 문구

**교훈**: A46에서 "ZP" 문자열만 훑어 `%TEMP%\WinUtil\subtitles`를 놓쳤다(A64에서 발견).
리브랜딩 스캔은 **현재 이름이 아니라 모든 과거 이름으로** 해야 한다.

### 3.2 셸 등록은 "등록한 그 순간"으로 굳는다
`ExplorerIntegration`이 레지스트리에 쓰는 값 중 **exe 절대 경로와 표시 문구는 재등록될 때만 갱신**된다.
- 그래서 A52로 모듈명을 바꿔도 이미 켜 둔 사용자의 우클릭 메뉴는 옛 문구 그대로다.
- A64로 exe명이 바뀌면서 등록된 경로가 없는 파일을 가리키게 됐고, 실기기에서 실제로
  .png 더블클릭이 '어떤 앱으로 열까요' 팝업으로 빠졌다 → **v0.89.0의 A78이 자동 복구를 넣음**
  (매 실행 시 `ReRegisterIfExeMoved`가 경로 어긋남을 감지해 켜져 있는 등록만 조용히 재기록).
- **Capabilities와 UserChoice(A38)는 ProgID만 참조**해서 경로 변화의 영향을 받지 않는다.
- A38의 자체 검증(`VerifyUserChoice`)은 **우리 해시 알고리즘 기준의 자기일관성 검사**다 —
  Windows가 실제로 수용하는지는 열어 봐야 안다. OS가 알고리즘을 바꾸면 "전부 성공"으로 보이면서
  실제로는 전부 무효가 되는 맹점이 있다(§5 첫 항목의 의심 지점).

### 3.3 하드웨어 모듈은 거의 전부 static (프로세스 공유)
`HardwareModule`의 폴러·섹션 캐시·구독자 수·리프레시 주기가 모두 `static`이고,
센서 선택(A18)·주기(A29)도 프로세스 단위 설정 키다. **A42에서 의도한 설계**(드라이버 핸들·WMI 조회 공유)라
통째로 뒤집으면 안 된다. 창마다 다른 그래프를 피닝하려면(A60) **공유할 것과 나눌 것을 갈라야** 한다 → **A70**.

### 3.4 빌드를 실제로 깨뜨린 것들 (재발 방지)
- **csproj/XAML 주석 안에 하이픈 두 개(`--`)** → MSB4025로 빌드 실패. XML 주석 문법 제약.
  (A64에서 `--mainExe`를 주석에 적었다가 실제로 깨짐.)
- **PowerShell 백틱 줄바꿈 뒤에 주석** → continuation이 깨진다. 백틱은 그 줄의 마지막 문자여야 한다.
- `resources.pri` — unpackaged WinUI는 exe 옆의 **고정 이름 `resources.pri`** 만 찾는다.
  없으면 시작 시 `XamlParseException`으로 조용히 죽는다(v0.5.5~0.5.7에 실제로 겪음).
  `AssemblyName`을 바꾸면 `$(TargetName).pri` 폴백 이름도 따라 바뀌므로 `release.yml`을 같이 고쳐야 한다.

## 4. 실기기 확인 대기 (사용자 몫) — **5개 버전치 밀려 있음**

한 번에 묶어서 확인하는 게 효율적이다.
※ v0.90.0(A82)은 문자열·메타데이터만 바꿨다 — 실기기 확인 항목은 **exe 속성 창의 회사/저작권 표기 정도**로 가볍다.

**v0.85.0 (A38) — 기본 앱 강제 지정**
- 연결 토글을 켰을 때 확장자들이 실제로 KOTU 기본 앱이 되는지
- `.pdf` 등 보호 확장자가 UCPD에 막혀 A25 딥링크로 폴백되는지
- 백신 오탐이 없는지 / 토글을 끄면 깨끗이 해제되는지

**v0.86.0 (A46) — ZP → KOTU**
- 첫 실행 시 구 ZP 우클릭 메뉴·파일 아이콘이 자동으로 사라지는지
- 트레이·타이틀바 아이콘이 새 "KO/TU" 아이콘으로 뜨는지
- 구 ZP 설치본 위에 KOTU Setup을 설치했을 때 충돌이 없는지

**v0.87.0 (A52·A56)**
- 제목표시줄이 `[2] KOTU Document — 파일명` 형태로 나오는지
- 우클릭 메뉴가 "KOTU-archive"로 바뀌는지 — **토글을 껐다 켜야 바뀔 것**(§3.2)

**v0.88.0 (A64) — exe 이름 ⚠️ 이번 건이 가장 중요**
- "Restart as admin"의 UAC 대화상자에 **`KOTU.exe`** 로 표시되는지 (이게 A64의 목적)
- 자동 업데이트 후 시작 메뉴·작업표시줄 바로가기가 새 exe를 가리키는지
- 설치 폴더에 구 `WinUtil.App.exe`가 남는지
- **파일 더블클릭이 여전히 동작하는지** — 안 되면 연결 토글을 껐다 켜야 한다(→ A78이 해결할 문제)

**v0.89.0 (A78) — exe 경로 자동 재등록 ⚠️ 사용자의 현재 고장을 고치는 버전**
- 업데이트 후 **아무 조작 없이** 앱을 한 번 실행하면 .png 등 더블클릭이 KOTU로 열리는지
  (첫 실행의 백그라운드 재등록이 고쳐야 정상 — 토글 조작 불필요)
- 우클릭 "Extract here"·"Compress"가 동작하는지 (verb command도 재기록 대상)
- 재등록 후 설정 화면의 "Default app for n/m" 숫자가 유지되는지 (UserChoice는 안 건드림)

**그 밖에 오래 밀린 것**: 오버레이 아크릴이 비디오 스왑체인 위에서 비치는지(v0.31.0),
Alt 리스트가 Zoom 화면공유에 보이는지(v0.32.0), 시크바 길이 불변(v0.49~0.53).

## 5. 사용자에게 물어야 할 미결 사항

`docs/REQUIREMENTS.md` 부록 B 끝의 "확인 필요"에도 있다.

- **A38 관련 미해결 관찰 2건** (2026-08-10 실기기, v0.88.0 시점):
  ① **.png 더블클릭 팝업이 토글 껐다 켠 뒤에도 남았다는 보고** — v0.89.0(A78)이 스스로 고치는지 우선 확인.
    그래도 남으면 UserChoice 해시를 Windows가 거부하는 것일 수 있다(§3.2의 자기일관성 맹점).
    그 경우 후속 항목 등재 필요: 쓰기 후 `AssocQueryString` 같은 **OS 측 확인**으로 검증을 바꾸고 실패 시 폴백.
  ② **KOTU-doc 토글 때만 Windows 설정 창이 뜨는 것은 설계된 폴백** — `.pdf` 등 UCPD 보호 확장자는
    강제 지정이 막혀 딥링크를 연다(정상). 다만 사용자가 매번 떠서 불편하다고 하면 억제 옵션 검토.
    또 그때 열린 **"기본 앱 > KOTU" 페이지가 비어 있었음** — Capabilities 등록 상태 확인 필요
    (재현되면 버그, 화면 로딩 문제였을 수도).
- **A54 트레이 아이콘 버그** — "버그 많음"이라고만 들었다. **구체 증상 목록이 없어 착수 불가.**
  (아이콘 중복/잔상, 창 닫아도 잔존, 모듈 전환 시 색 미반영, 클릭 무반응 등 중 무엇인지)
- **A68 인스턴스 색 팔레트** — A2의 9색을 그대로 쓸지, 10번째 이상 인스턴스는 어떻게 할지
- **A70 인스턴스별 설정 저장 키** — 창 번호는 실행마다 바뀌어서 그대로 쓸 수 없다
- **A73의 50ms** — 실측 부하 확인 후 유지 여부 판단 (센서 폴링이 못 따라가면 무의미)

## 7. 최근 3개 버전 요약 (배경만 — 상세는 git log)

- **v0.86.0 (A46)** ZP → KOTU. 범위는 표시명 + 시스템 등록 ID. **기존 사용자 설정 이관 없음**(사용자 확정) —
  대신 구 브랜드 레지스트리는 첫 실행에 1회 자동 청소. 앱 아이콘은 4글자가 16px에서 뭉개져 **"KO"/"TU" 2줄**로 확정.
- **v0.87.0 (A35·A52·A53·A56)** 표시명 단수형 + ZIP→Archive, New Instance 문구, 제목에 인스턴스 번호,
  연결 섹션 순서. 우클릭 메뉴 라벨의 하드코딩을 없애 모듈 `BrandName`을 따르게 함.
- **v0.88.0 (A64)** exe·어셈블리·프로젝트·네임스페이스 전면 rename. A46의 "표시명만" 결정을 대체.
  계기는 UAC에 `WinUtil.App.exe`가 보인 것 — 사용자 관심사는 **"WinUtil이라는 단어"** 이지
  "게시자: 알 수 없음"(코드 서명)이 **아니다**. 저장소도 `zpro` → `kotu`로 변경됨.
- **v0.89.0 (A78)** 시작 시 셸 등록의 exe 경로 어긋남 자동 복구. 계기는 실기기에서 .png 더블클릭이
  '어떤 앱으로 열까요'로 빠진 것(A64의 예고된 부작용). 순수 로직은 Core `ShellCommand`로 분리해
  단위 테스트(ShellCommandTests). 구현 결정은 REQUIREMENTS 부록 B #25.
- **v0.90.0 (A82)** 개인 실명 제거 + 저작 주체를 **ZP Studios** 한 이름으로 통일
  (LICENSE·`Directory.Build.props`·release.yml `packAuthors`·site 푸터 — **표기를 바꿀 땐 이 4곳을 함께 본다**).
  git 이력은 재작성하지 않기로 확정 → **v0.89.0 이전 커밋의 작성자 표기는 GitHub에 그대로 남는다**(수용된 한계).
  로컬 `git config`에 이름·메일이 고정돼 있으니 커밋할 때 `-c user.name=...` 오버라이드를 쓰지 말 것.
  ※ 함정 하나: XML 주석에 `--packAuthors`라고 적었다가 하이픈 2연속으로 props 파싱이 깨졌다(커밋 전에 잡음).
