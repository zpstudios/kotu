# 전역 압축 백그라운드 작업 — A361 (v0.358.0)

2026-09-08 · `codex/archive-background-jobs`

사용자가 전역 압축 작업 진행을 승인했다. 압축 실행의 수명을 창·압축 뷰와 분리하고,
모든 창에서 같은 작업을 확인·취소·암호 응답할 수 있도록 한다. 브랜치 구현과 로컬 빌드·
회귀 및 GitHub 설치 검증을 완료했다. A361은 master 병합·정식 발행 전이며,
아래 범위는 코드 정독과 테스트를 기준으로 기록한다.

## 동작과 책임

- `BackgroundJobService`와 `ArchiveJobCoordinator`를 앱에 한 번 등록한다. 공통 서비스가
  실행·취소·암호 대기 및 제한된 완료 이력을 소유하고, 조정자는 작업별 실행 워커를 소유한다.
  창과 압축 뷰는 작업 상태를 표시하고 명령을 전달한다. 뷰를 바꾸거나 창 하나를 닫아도
  해당 뷰에서 시작한 작업은 남는다. ZIP/7z 생성, 압축 해제, 항목 임시 해제가 대상이다.
  압축 목록·정보 조회와 생성 옵션 선택은 화면 수명에 남으며, 목록을 여는 암호 대화상자도
  화면을 떠나면 닫는다. 이미 시작한 해제 작업의 암호 재시도는 전역 패널이 담당한다.
- 작업 시작 시 입력을 확정한다. 이후 파일 선택이나 뷰 경로가 바뀌어도 이미 시작한 작업의
  원본·대상·옵션이 바뀌지 않는다. 작업 상태 스냅샷에는 암호를 포함하지 않는다.
- `Running`, `WaitingForPassword`, `Canceling` 및 성공·실패·취소 완료를 구분한다.
  취소 요청은 실제 작업 종료와 다르다. 작업과 네이티브 엔진의 협조가 끝나야 완료로 표시한다.
  취소 콜백은 UI 밖에서 실행하며 취소 완료와 실행 완료의 경쟁을 고려해 자원을 정리한다.
- 모든 창의 공통 패널이 같은 상태를 표시한다. 사용자가 패널을 명시적으로 열어 작업을
  확인하고, 암호가 필요한 작업에는 패널 안에서 응답한다. 암호 대기를 모달 창 수명에 묶지 않는다.
  작업 ID와 암호 요청 ID를 함께 확인하여 다른 창의 오래된 입력을 거절한다. 입력 중인 행은
  진행 통지마다 재생성하지 않으며 패널 닫기·요청 변경·창 종료 시 입력란을 비운다.
- 마지막 창 닫기, 전체 앱 종료, 업데이트 적용, 관리자 권한 재시작은 진행 중이거나
  암호를 기다리는 작업을 조용히 중단하지 않는다. 작업이 있으면 패널과 안내를 보여주고
  종료/재시작을 미룬다. 사용자가 작업을 마치거나 취소한 뒤 다시 요청한다. 마지막 창의
  실제 닫기와 재시작 준비는 유휴 상태를 원자적으로 확보하여 새 작업 시작도 막는다.
  UAC 취소·재시작 실패 시에는 시작 제한을 해제한다.
- 완료 이력은 기본 50건으로 제한하며 사용자가 완료 행을 닫을 수 있다. 활성 작업은
  이력 정리 때문에 삭제하지 않는다. 일반 생성·해제는 자동으로 탐색기를 열지 않고
  완료 행의 `Open folder`로 위치를 연다. 항목 더블클릭은 시작한 뷰가 여전히 살아 있을 때만
  임시 해제 결과를 기본 앱으로 연다. 뷰를 떠난 경우 결과 위치는 공통 패널에서 연다.

## 기대 흐름과 회귀 검사

| 상황 | 확인할 결과 |
|---|---|
| 작업 시작 후 파일 선택 변경 | 시작 시 확정한 입력으로 계속 실행 |
| 다른 모듈로 전환 / 시작한 창 닫기 | 작업 지속, 다른 창에서 동일 상태 확인 |
| 암호 필요 / 틀린 암호 | 전역 대기 표시와 재응답, 비밀값 미노출 |

| 실행 중 취소 | 취소 요청 표시 후 실제 종료와 일치하는 완료 상태 |
| 여러 창에서 동시 취소·암호 응답 | 중복 처리나 잘못된 작업 응답 없음 |
| 성공·실패·취소 후 패널 재열기 | 일관된 최종 상태, 제한된 이력 유지 |
| 마지막 창·전체 종료·업데이트·관리자 재시작 | 활성 작업을 알리지 않고 종료하지 않음 |

새 공식 Release나 태그를 만들지 않았다. 실제 암호 입력·다중 창 작업 UI를 자동 조작한 결과는 아니다.
독립 코드 검토에서 작업 입력의 불변성, 암호 노출, 뷰 해제 후 콜백, 모든 종료 진입점을
확인했다. 발견한 키보드 입력 누락과 임시 항목의 셸 실행 예외 경로를 보완했다.
Jobs 버튼과 패널 전체에서 전역 단축키·압축 문자 키를 양보하고, PasswordBox Enter는
암호 응답으로 전달한다. Esc는 패널을 먼저 닫는다. 임시 항목 실행은 워커에서 수행하고
실패 시 앱을 종료시키지 않으며, 뷰 해제의 가시성을 보장하는 상태 검사 후 실행한다.

## 한계와 수동 확인

작업은 앱 프로세스 안에서 실행한다. OS 종료·강제 프로세스 종료·충돌 후 자동 복구나
프로세스를 넘는 영속 실행은 이번 범위가 아니다. 협조하지 않는 네이티브 작업을 강제 종료하는
기능도 아니다. 취소·실패 시 이미 생성된 파일의 처리 방식은 기존 엔진 계약과 구현 검토로
확인하며, 모든 압축 작업의 원자적 되돌리기를 보장하지 않는다.

수동 확인: 큰 압축 파일 작업 도중 모듈·창 전환, 다른 창에서 작업 취소, 암호 파일의
대기·오답·재입력, 여러 창의 상태 동기화, 마지막 창 닫기와 전체 종료 안내,
업데이트 적용·관리자 재시작 시 활성 작업 보호. 자동 테스트가 실제 암호 UI 조작이나
모든 압축 형식·네이티브 엔진 동작을 대신하지는 않는다. 특히 암호의 숫자·대문자·문자 입력,
Tab으로 Jobs 버튼에 진입 후 Enter, 암호 입력 중 Enter·Esc와 여러 창의 입력 대기를 확인한다.
이미 OS에 전달된 연결 프로그램 실행까지 뷰 해제로 되돌리는 기능은 아니다.
