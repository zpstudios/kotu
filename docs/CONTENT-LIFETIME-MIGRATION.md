# 구조 개선 4단계: 콘텐츠 수명과 화면 상태 분리

2026-09-07 · v0.356.0 · A359 · `codex/architecture-document-session`

사용자가 승인한 3~5단계 직렬 진행의 네 번째 단계다. 기본 브랜치 병합과 정식 Release 발행은
포함하지 않는다. 이 단계는 콘텐츠 계약의 부착 수명과 All Readable의 비화면 상태를 분리한다.
창 제목·모드·사이드바·XAML 트리와 네이티브 워커의 실제 해제는 기존 소유자에 남는다.

## 소유권과 교체 순서

`KOTU.Core.Content.ContentContractSession`은 한 번의 콘텐츠 부착에 속하는 계약 이벤트를
구독하고 해제한다. 워커 발화 시에는 원자적 해제 표시만 읽고, 디스패치 안에서 현재 뷰의
동일성을 확인한다. 이미 예약된 콜백은 해제된 부착을 되살릴 수 없다. 같은 객체를 다시
부착해도 이전 세션은 무효다. UI에서 발화한 중첩 통지는 다시 큐에 넣지 않아, 자식 검사와
셸 처리 사이에 별도 큐가 남지 않는다.

`ChildContentHost`는 All Readable 자식, 열린 경로, 더티 통지와 탐색 순서 및 계약 위임을
담당한다. 요청 경로·저장 경로 통지는 중계만 하고, 실제 열린 경로는 ContentOpened와
UntitledOpened에서 변경한다. 초기 컨텍스트 경로를 사용하는 기존 동작은 유지한다.
정보·인쇄 페이지·닫기 확인의 비동기 완료도 해당 자식 부착이 그대로일 때만 유효하다.

All Readable 교체는 구독 무효화 → 별도 하단 바 제거 → 센터 제거(Unloaded) → 더티 및 빈
상태 통지 순서다. 실패한 뷰 생성은 이전 경로와 바를 남기지 않는다. Archive의 Back 요청은
IContentCloseRequestSource로 셸까지 전달한다. 인쇄·새 창·콘텐츠 닫기는 행동 요청이므로
자식 교체만으로 발생하지 않는다. 트레이·재생·미디어 이웃 상태는 교체 때 다시 알린다.

MainWindow의 모듈·설정·미지원 파일 교체는 같은 구독 해제와 재부착 경로를 사용한다.
별도 하단 바·패널과 미디어 전송 대상을 먼저 해제한다. 창 종료도 구독을 무효화한다.
닫기 다이얼로그는 기존 단일 진입 가드를 유지하며, 완료 후 셸과 중첩 자식 부착을 다시
검사한다. 사용자가 버리기를 선택하면 더티 상태가 남아 있어도 닫기를 허용하는 계약은 유지한다.

## 회귀 검사

실제 Core 객체와 가짜 계약 콘텐츠, 수동 디스패치 큐를 사용한다.

- 워커에서 UI 동일성 검사를 호출하지 않음, 예약된 이전 이벤트 폐기, 같은 객체 재부착.
- 모든 계약 구독 해제, 반복 해제, Unloaded에 해당하는 제거 콜백의 재진입과 더티 초기화.
- 중첩 전달은 큐 한 번만 사용, 상태 통지 도중 자식 교체 시 나머지 옛 통지 폐기.
- 닫기 거절·예외·버리기, 셸 또는 자식 교체 뒤 늦은 닫기 승인 무효화.
- 로드·요청·저장·무제 경로 구분, 탐색 순서 재주입, 행동 요청 단일 중계.
- 오디오 미디어 조작과 영상 재생 표면 구분, 빈 계약 기본값, 정보·인쇄의 늦은 결과 폐기.

로컬 .NET SDK 8.0.424에서 전체 Release/x64 빌드 성공(경고 0·오류 0). Windows의 실제
파일·미디어 접근 환경에서 8개 테스트 프로젝트 304건 통과(실패/건너뜀 0), 기존 285건에
새 수명 회귀 19건을 추가했다. Core 단독 127건도 통과했다. 구조 검사 19개 프로젝트와
변경 diff의 공백·한글 이스케이프 검사도 통과했다. 독립 검토에서 발견한 워커 스레드의
UI 동일성 접근과 늦은 정보·인쇄 결과 문제를 수정하고 회귀 테스트에 포함했다.
검증 로그는 로컬의 무시 대상 `artifacts/phase4-build.log`, `artifacts/phase4-tests.log`,
`TestResults/phase4-full`에 남긴다.
[GitHub build 34130716113](https://github.com/zpstudios/kotu/actions/runs/34130716113)은
소스 커밋 `8d8adb4`에서 전체 성공했다. 설치 EXE 패키징·실제 설치·설치 파일 정합성·
설치본 시작 검사 및 아티팩트 업로드가 통과했다. 기본 브랜치 병합과 정식 Release 발행은
하지 않았다. Core 테스트는 실제 WinUI 레이아웃이나 네이티브 재생을 실행하는 검사가 아니다.

수동 확인: All Readable에서 문서 편집 후 영상·사진·압축으로 전환, 저장 확인 취소와 버리기,
압축 Back으로 콘텐츠 닫기, 재생 중 설정·미지원 파일로 전환, 인쇄·정보 조회 중 파일 전환,
창 닫기 직전 늦은 로드 통지. 네이티브 워커 종료 순서와 UI COM 호출 금지 규칙은 변경하지 않는다.
