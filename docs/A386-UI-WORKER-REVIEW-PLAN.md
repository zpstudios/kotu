# A386 — UI·워커 분리 검토와 개선 인수인계

작성: 2026-10-07 · 기준 제품: v0.386.0 / `bdbbd6b`

## 상태와 작업 범위

**후속 상태(2026-10-07)**: 사용자가 전수 감사·우선 개선1~4 구현·검증·버전별 push를 승인했다.
v0.387.0~v0.390.0으로 순차 구현했으며 정적 호출 경로·추가 발견·검증/미검증 구분은
[A386 감사 결과](A386-UI-WORKER-AUDIT.md)를 따른다. 아래는 작업 전 계획의 보존본이다.

사용자는 이 세션에서는 개선 사항 정리만 요청했고, 실제 작업 지시는 새 세션에서 할 예정이다.
아래는 코드 1차 검토 결과와 다음 작업의 완료 기준이다. 전수 감사 완료 보고서가 아니며,
아래 개선은 아직 구현하지 않았다. 실제 UI 지연·네트워크 지연·큐 길이는 측정하지 않았다.
제품 코드·버전은 이 문서 정리로 변경하지 않는다.

A386은 썸네일·녹화에 한정하지 않는다. 앱 셸, 탐색기·파일 작업, 설정·업데이트·진단,
문서·PDF·오피스 미리보기, 이미지, 영상·오디오, 압축, 하드웨어와 공통 워커 계약이 대상이다.
UI 객체 조작·렌더·입력·피커·대화상자는 UI에 남긴다. UI 타이머가 있다는 이유만으로
분리 실패로 판정하지 않고, 콜백에서 실제 수행하는 I/O·COM·CPU 작업과 대기 시간을 확인한다.

| 영역 | 확인한 분리 | 주요 코드 |
|---|---|---|

| 이미지 | 파일 읽기·디코딩·변환·폴더 목록을 워커에서 처리 | `ImageViewerView.Worker`, `ReadImageFile`, `ImageFolderNavigator.Create` |
| 문서 | 본문 읽기·쓰기·Markdown 파싱을 워커에서 처리 | `DocumentView.ReadTextSmart/SaveCoreAsync`, `MarkdownParser.Parse` |
| 영상·오디오 | 엔진 생성·해제, 폴더 재생 목록, 영상 자막 탐지·변환을 워커에서 처리 | 각 `Worker`, `EnsurePlaylist`, `SubtitleFileLocator/SubtitleCharset` |
| 압축 | 조회·작업 실행에 워커/백그라운드 작업 사용 | `ArchiveView`, `ArchiveJobCoordinator` |

## 우선 개선 1 — 설정 저장과 공용 잠금

**확인한 사실**

- `JsonSettingsService.Save`는 `_lock` 안에서 디렉터리 생성·JSON 직렬화·동기 파일 쓰기를 수행한다.
- `Get/Set`도 같은 잠금을 사용하므로 Save를 워커로 옮기는 것만으로 UI 대기가 모두 없어지지 않는다.
- `SettingsView`의 배율 선택 콜백에서 `Set` 뒤 `Save`를 직접 호출한다.
- `DocumentView.FlushZoomSave`는 UI DispatcherTimer와 Unloaded 경로에서 직접 저장한다.
- 영상·오디오 설정 및 종료 경로, 셸에서도 직접 Save 호출이 있다. 전체 호출자는 후속 감사 대상이다.

근거: [설정 서비스](../src/KOTU.Core/Settings/JsonSettingsService.cs),
[설정 화면](../src/KOTU.App/SettingsView.xaml.cs),
[문서 화면](../src/KOTU.Module.Document/DocumentView.xaml.cs).

**권장 변경 / 완료 기준**

- 설정의 메모리 반영과 실제 파일 저장을 분리한다. 잠금은 스냅샷 취득에만 짧게 사용하고
  직렬화·디스크 쓰기는 잠금 밖의 직렬 저장 경로에서 처리한다.
- 연속 변경을 합쳐 저장하되 오래된 스냅샷이 최신 값을 덮어쓰지 않도록 순서/버전 계약을 정한다.
- 저장 오류를 관측하고 사용자에게 필요한 오류를 알린다. 오류를 삼키는 정리용 `Post`로 대체하지 않는다.
- 종료·모듈 전환에서 보류된 마지막 설정의 저장을 보장한다. 동기 Wait/Result로 UI를 막지 않는다.
- 메모리 전용 Standalone 정책, 기존 설정 키·창 간 알림, 녹화 폴더 설정의 저장 실패 처리를 보존한다.
- 느린 저장 중 UI의 Get/Set이 디스크 쓰기 종료를 기다리지 않는 테스트와 최신 값·저장 실패·종료 검증을 한다.

우선순위: 높음. 실제 멈춤의 빈도·시간은 미측정이다.

## 우선 개선 2 — UI에 남은 파일·폴더 존재 조회

**확인한 사실**

- `ExplorerPane.OnWatchDebounceExpired`가 UI에서 `Directory.Exists`로 상위 경로를 반복 확인한다.
- `VideoPlayerView.MoveToNeighbor`가 UI 입력 경로에서 `File.Exists(target)`을 호출한다.
- 셸의 경로 선택·복원, 이미지·영상 초기 경로 확인, 이름 변경 시작 등에도 동기 조회가 남아 있다.

근거: [탐색기](../src/KOTU.App/ExplorerPane.xaml.cs),
[영상 화면](../src/KOTU.Module.Video/VideoPlayerView.xaml.cs),
[셸](../src/KOTU.App/MainWindow.xaml.cs), [이름 변경](../src/KOTU.App/ExplorerRenameBox.cs).

**권장 변경 / 완료 기준**

- 사용자 파일·네트워크·이동식 드라이브 경로의 조회를 우선 워커로 옮긴다.
- 비동기 결과에 경로·탐색 세대·뷰 수명을 대조한다. 조회 중 새 폴더/파일로 이동하면 이전 결과는 버린다.
- 버튼 연속 입력·감시 이벤트 폭주를 합치고, 오래된 결과가 새 탐색 위치나 재생 목록을 바꾸지 않게 한다.
- 존재 확인은 성공을 보장하지 않는다. 이후 실제 열기/작업 실패 처리도 보존한다.
- 폴더 소실 시 상위 이동, 재생 목록에서 소실 파일 제거 등 기존 동작을 유지한다.
- 소스 검색 결과만으로 모두 UI 위반이라고 판단하지 않는다. 워커 안의 호출과 UI 시작 전 호출을 구분한다.
- 느린 조회를 주입해 빠른 이동·해제·경로 소실 회귀를 확인한다. 실제 네트워크 응답성은 별도 측정한다.

우선순위: 높음. 끊긴 경로에서 UI가 기다릴 가능성이 있지만 실제 장애 재현은 하지 않았다.

## 우선 개선 3 — 창 아이콘용 파일 정보 캐시

**확인한 사실**

`MainWindow.RefreshShellIcons` → `OpenFileIconInfo`에서 파일 존재 확인과 `FileInfo.Length`를
동기로 수행한다. 아이콘 캐시 키를 비교하기 전에 이 조회를 한다.

근거: [셸 아이콘 갱신](../src/KOTU.App/MainWindow.xaml.cs).

**권장 변경 / 완료 기준**

- 워커가 조회한 경로별 파일 정보를 캐시하고 UI에서는 캐시로 아이콘을 그린다.
- 파일 변경·저장·전환·삭제에 캐시를 갱신/무효화한다. 용량을 모르면 기존 미확인 표시를 유지한다.
- 결과에 현재 파일·창 수명을 대조하고 낡은 조회가 새 파일 아이콘을 덮어쓰지 않게 한다.
- 크기 변경과 빠른 파일 전환, 조회 실패, 창 닫힘 회귀를 확인한다.

우선순위: 중간. 실제 갱신 빈도와 비용은 측정 전이다.

## 우선 개선 4 — 드라이브 조회 요청 누적 방지

**확인한 사실**

`DriveStrip`은 30초마다 `Refresh`를 호출하고 매번 직렬 워커에 조회를 넣는다.
`_seq/_active`로 늦은 결과의 표시를 막지만, 실행 중 조회의 중복 요청을 합치는 장치는 없다.
공통 `ModuleWorker` 큐도 상한 없는 `BlockingCollection`이다.

근거: [드라이브 줄](../src/KOTU.App/Controls/DriveStrip.xaml.cs),
[공통 워커](../src/KOTU.Core/Threading/ModuleWorker.cs).

**권장 변경 / 완료 기준**

- 조회 하나만 실행하고 중복 요청은 필요하다면 최신 요청 하나로 합친다.
- 비활성화/해제 시 낡은 대기 요청을 취소하고, 다시 표시하면 최신 조회를 보장한다.
- 취소 불가능한 네이티브 호출은 UI로 옮기거나 강제 종료하지 않는다. 늦은 결과 반영을 막는다.
- 지연/실패/해제 시에도 실행 중 플래그가 해제되며 요청 수가 누적되지 않는 검증을 한다.
- 공통 워커 큐 정책은 다른 호출자의 순서·정리 보장에 영향을 주므로 별도 감사 후 결정한다.

우선순위: 중간. 현재 요청 누적이 실환경에서 발생했다는 측정 결과는 없다.

## 전수 감사에서 추가로 확인할 사항

- 모든 사용자 흐름의 진입점 → 실제 작업 → UI 반영 → 해제 경로를 모듈별로 기록한다.
- WinRT/COM·파일/레지스트리·프로세스 호출과 큰 파싱·변환·전체 목록 처리의 실행 스레드를 판별한다.
- 워커 취소가 큐 진입 전/실행 중 모두 유효한지, 늦은 완료가 닫힌 뷰를 갱신하는지 확인한다.
- `ModuleWorkerPool`의 고정 순환 배정에 긴 작업이 섞일 때 지연이 있는지 측정한다.
  풀 변경이나 스레드 증설은 측정 없이 시행하지 않는다.
- 폴더 트리 비동기 로드, 모듈 전환·재로드, Watcher/Timer 이벤트 해제와 예외 관측을 확인한다.
- 오디오·영상의 네이티브 재생 제어 호출도 확인한다. UI 스레드 필수 호출과 비용 있는 호출을 구분한다.
- UI 결과 반영이 큰 목록/문서에서 한 프레임을 오래 점유하는지 확인한다. UI 객체 생성은 워커로 옮기지 않는다.
- 실제 측정에는 큰 폴더·대형 문서, 느린/소실 경로, 빠른 연속 이동, 창 여러 개, 종료·취소를 포함한다.

## 새 세션 작업 순서와 결과물

1. 이 문서와 REQUIREMENTS의 A386, ARCHITECTURE 8/11장, 현재 저장소 지침을 읽는다.
2. 전체 호출 경로 표를 보강하고 위 네 항목의 현재 존재 여부·변경 범위를 재확인한다.
3. 사용자 작업 지시에 따라 우선 개선 1→2→3→4 순서로 범위를 나누어 구현한다.
4. 각 범위에 관련 회귀·실패/취소/해제 검증과 배포용 빌드, 구조/릴리스 검사를 수행한다.
5. 코드 사실·측정 결과·미검증 후보를 구분해 보고하고 REQUIREMENTS/HANDOVER를 갱신한다.
   빌드 통과를 전수 감사나 실제 UI 응답성 검증 완료로 표현하지 않는다.
6. 구현 커밋은 저장소의 버전·커밋·push 규칙을 따른다. 등록된 다른 UI 백로그는 함께 구현하지 않는다.

최종 감사 결과에는 모듈별 판정, 수정한 호출 경로, 잔여 문제, 시험 결과, 실제 측정/미측정 범위를 남긴다.
