# A387 썸네일 파일명 확대

- `ThumbnailExplorer.xaml`의 공용 TileCaption을 FontSize 11에서 14 DIP로 확대한다. S1과 S4가 같은 템플릿을 사용하므로 양쪽에 적용된다.
- 캡션의 Auto 행 높이 증가가 미리보기 영역을 줄이지 않도록 `ApplyTileSize`의 ItemsWrapGrid.ItemHeight를 타일 폭 + 4 DIP로 조정한다. 기본 글꼴/배율의 줄 높이 증가분에 맞춘 여유이며 타일 폭과 열 수 계산은 유지한다. 고정 캡션 높이를 사용하지 않으므로 Windows 텍스트 확대 시 잘림을 강제하지 않는다.
- 긴 파일명은 기존 CharacterEllipsis와 전체 파일명 툴팁을 유지한다.
- `ExplorerRenameBox.Begin`이 nameBlock.FontSize와 Margin을 편집 TextBox에 복사하므로 이름 변경 중에도 같은 14 DIP가 적용된다.
- 가상화된 컨테이너는 같은 XAML 템플릿을 재사용하므로 개별 컨테이너 상태나 후처리가 필요 없다. 셀 크기는 기존 ApplyTileSize 경로에서 전체에 적용한다.
- 이미지 디코딩, 리샘플링, 작업 스레드 및 UI 반영 경로에는 변경이 없다.

검증: XAML XML 파싱 및 git diff 공백 검사 통과. App x64 로컬 빌드 통과(TreatWarningsAsErrors=true, 경고 0개/오류 0개).

실기기 확인: S1/S4 파일명 가독성, 캡션/미리보기 간격, 긴 이름과 이름 변경, 작은 창과 UI 배율 변경은 GUI 확인이 필요하다. 셀 높이 +4 DIP는 기본 글꼴의 증가분 보정이며 OS 텍스트 확대까지 이전 미리보기 높이를 정확히 보장하는 수치는 아니다. 이번 검증에서는 GUI를 실행하지 않았다.

## A433 고정 열 수와 조작부 비례 축소 — v0.433.7

사용자 정정: 열 수가 고정인 것이 앱의 컨셉이다. 타일이 작아질 때 체크박스 등 조작부가 상대적으로 지나치게 커지는 문제를 조작부 크기로 해결한다. v0.433.6의 자동 열 감소와 그 설치 요청은 철회했다.

패널별 요청 6/9/12열과 기존 `floor(가용 폭/열 수)`, 셀 높이 `max(폭+4,64)`를 유지한다. 타일 체크박스·클라우드 배지·미리보기 대기 배지는 각자의 여백과 함께 비례 축소한다. 실제 타일 폭 96 DIP 이상에서는 기존 크기이며 그보다 작으면 폭/96 비율로 줄인다. 96 DIP는 조작부 축소 기준이지 최소 타일 폭이나 열 수 전환 경계가 아니다.

기존 CheckBox와 스킨을 Viewbox 안에서 축소해 표시와 실제 클릭 영역을 함께 맞춘다. 고정된 glyph 치수로 내부 슬롯을 단정하지 않고 여백을 포함한 자연 DesiredSize를 측정해 축소한다. 고정 슬롯을 쓴 첫 실행본의 체크 하단 잘림은 자연 크기 측정으로 바꾼 뒤 Ink/Humanist의 좁은·넓은 창에서 재현되지 않았다. 큰 창으로 돌아오면 원래 크기까지만 복원한다. 목록 행·캡션 14 DIP·공통 버튼·선택/체크 데이터는 바꾸지 않는다.

Core 753개, 추가 수정의 독립 검토와 일반 빌드를 통과했다. 최종 실행본에서 6/9/12열 고정, 체크 외곽과 클릭 영역, Space·Right, 보기·디자인·크기 왕복 및 96폴더 스크롤 후 선택·체크 보존을 확인했다. 실제 배지 출현과 다른 DPI 등 미검수 범위는 [실기기 기록](../../DEVICE-CHECKS.md#native-media)을 따른다. 공식 배포·이 PC 설치 대조는 진행 중이다.

## A433 작은 창의 타일 공간 — v0.433.6

**사용자 정정으로 취소된 구현:** 2026-11-24 사용자는 열 수 고정이 앱의 컨셉이며, 작은 타일에 비해 고정 크기 조작부가 과도하게 커지는 문제라고 명확히 했다. 아래 v0.433.6 자동 열 감소는 채택된 제품 방향이 아니다. 다음 정정판은 열 수를 유지하고 조작부·배지·여백을 축소한다.

v0.433.6은 체크박스 20 DIP·파일명·상태 배지의 크기는 유지하고, 가용 폭에 96 DIP 셀이 들어가지 않을 때만 실제 열 수를 줄인다. 요청 열 수 6/9/12는 별도로 보존하므로 충분히 넓히면 원래 밀도로 돌아간다. 96 DIP는 선택 질문 미응답 후 진행을 고지한 기본안이며 사용자가 직접 지정한 수치가 아니다.

`ExplorerTileLayout.Measure`는 요청 열 수와 `floor(가용 폭/96)` 중 작은 값을 최소 1열로 사용한다. 셀 폭은 가용 폭을 넘지 않으며, 높이는 기존 `max(폭+4,64)`다. App은 padding·border를 제외한 폭을 실제 스크롤 뷰포트 폭으로 제한한다. 크기 변경 시 인스턴스별 큐에서 한 번 계산하고 같은 크기는 재대입하지 않는다. 선택·체크·목록 데이터와 매 프레임 작업은 추가하지 않는다.

Core 741개와 독립 검토, 일반 빌드·Ink/Humanist의 좁은 창 및 넓은 6/9/12열·스크롤·보기 왕복 검수를 마쳤다. 스크롤의 논리 위치 계약은 [A417](explorer-refresh-A417.md#세션보기입력)을 유지하며 화면 상단 행·픽셀 동일성을 보장하지 않는다. 실제 관측과 복원 방법은 [실기기 기록](../../DEVICE-CHECKS.md#native-media), `artifacts/a433-review/product-visual-review.json`을 따른다.
