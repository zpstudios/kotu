# A427 전체 UI 디자인과 선택 화면

## 승인 범위

2026-11-21 사용자는 좌우 패널·중앙 영역·하단 작업표시줄 등 전체 UI를 통일하는 11개 후보를 모두 제품에 반영하도록 승인했다. 색만 다른 유사안은 별도 디자인으로 늘리지 않는다. 원본 비교 시안은 로컬 `artifacts/ui-design-candidates/kotu-design-directions.html`, 사용자 첨부 화면은 같은 폴더의 `reference.png`에 있다. 시안의 마지막 CSS 재정의를 포함해 비교한다.

승인한 방향은 정밀 선형, 둥근 휴머니스트, 솔리드 픽토그램, 편집물 타이포그래피, 터미널 계기판, 촉각적 기계, 굵은 프레임, 접힌 종이, 입체 타일, 픽셀 격자, 손그림 잉크다. 각각 선끝·면·글자의 역할·체크 표시·컨테이너 형태까지 구별한다. 색·굵기만 바꾼 11개 항목으로 완료 처리하지 않는다.

| 저장 ID | 영어 표시 이름 | 구별할 조형 |
|---|---|---|
| `precision` | Precision line | 가는 선과 절제된 평면 경계 |
| `humanist` | Rounded humanist | 둥근 선끝·패널·버튼 |
| `solid` | Solid pictograms | 채운 아이콘과 반전된 작업 막대 |
| `editorial` | Editorial typography | 명조 제목·파일명, 가는 가로 구분선 |

## 오프라인 글꼴

시스템 글꼴은 이름으로 참조하고 복사하지 않는다. Nunito Sans와 Barlow Semi Condensed의 한글은 Malgun Gothic으로 보완한다. 편집물의 한글 제목에는 선택 설치인 Batang 대신 Nanum Myeongjo를 동봉한다. 터미널·픽셀·손그림은 한영을 같은 가족으로 표시한다.

동봉 대상은 Nunito Sans Regular/SemiBold, Barlow Semi Condensed Regular/SemiBold, Nanum Myeongjo Regular/Bold, Nanum Gothic Coding Regular/Bold, Galmuri11 Regular/Bold, Gaegu Regular/Bold다. 원본을 수정하지 않고 각 가족의 SIL OFL 1.1 저작권·라이선스 전문과 함께 배포한다. 다운로드 후 TTF 내부 family 이름·문자 지원·크기·해시를 기계적으로 확인한다.

원본 검증에서 두 Nanum 가족과 Galmuri11은 각 두께 모두 한글 음절 11,172자와 인쇄 가능한 ASCII 95자를 포함했다. Gaegu는 한글 2,350자만 포함하고 백틱이 없어 드문 한글·누락 기호에 시스템 보완 글꼴이 필요하다. WinUI 파일 참조의 가족 이름은 `NanumMyeongjo`, `NanumGothicCoding`처럼 공백이 없다. 검증 원본·라이선스·출처와 해시는 로컬 `artifacts/a427-review/fonts/manifest.json`에 있다. 실제 네이티브 렌더링 확인은 별도 단계다.

- [Nunito Sans 원본](https://github.com/googlefonts/NunitoSans/tree/058bd7a2f33d6ad5ef1df985b3db403622016a8c/fonts/ttf)과 같은 커밋의 `OFL.txt`.
- [Google Fonts 고정 원본](https://github.com/google/fonts/tree/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl)의 `barlowsemicondensed`, `nanummyeongjo`, `nanumgothiccoding`, `gaegu` 폴더와 각 `OFL.txt`.
- [Galmuri 고정 원본](https://github.com/quiple/galmuri/tree/bdb86ae89466a361eb8df861222736b81ff975ef/dist)의 `Galmuri11.ttf`, `Galmuri11-Bold.ttf`, `LICENSE.txt`.

## 설정에서 선택

- 2026-11-23 [A428](../../REQUIREMENTS.md#a428) 요청으로 선택 화면은 **갤러리 하나**로 제공한다. Single view, 보기 전환 라디오, 이전/다음, 별도 큰 미리보기, Show applied design, Open single view와 별도 적용 버튼은 제거한다.
- 갤러리는 전체 화면 썸네일 11개를 적응형 열로 나란히 보여 준다. 높이가 부족하면 설정 화면을 스크롤한다. 카드를 선택하면 그 디자인을 즉시 적용하며 선택 대기·미리보기 상태를 따로 두지 않는다.
- 현재 적용된 카드에만 **Applied** 표식과 강조 테두리를 표시한다. 다른 설정 창에서 바꿔도 같은 표식으로 갱신한다.
- 카드의 작은 예시는 같은 파일·한영 이름·체크·현재 선택·비활성 상태를 사용한다. 실제 사용자 파일이나 모듈을 열지 않으며 실제 UI와 같은 디자인 정의를 사용한다.
- 새 기본값은 Precision line이다. 안정적인 문자열 ID를 `display.design`에 저장하고 알 수 없는 ID는 기본값으로 처리한다. 기존 `display.thinControls` 키를 삭제하거나 덮어쓰지 않는다.

제거 기능의 복원 기준은 [v0.433.0 제품 커밋](https://github.com/zpstudios/kotu/commit/db101e765d12a35a77f954d2674b18bb912221cc)이다. 당시 `DesignPicker.cs`, `DesignSelection.cs`와 관련 테스트·가이드가 Git에 보존된다. 복원 시 그 구현과 A428 변경을 비교해 필요한 부분을 되살리고 검증한다. 현재 앱에 선택 옵션·숨은 전환·사용하지 않는 구현을 남기거나 별도 소스 보관 사본을 만들지 않는다.

## 적용과 보존

- 열린 창과 나중에 생성되는 창·메뉴·가상화된 목록 요소에 같은 선택을 적용한다. Standalone도 현재 세션 안에서 선택할 수 있다.
- 적용 때문에 창이나 모듈을 다시 만들거나 파일을 다시 열지 않는다. 미저장 문서·재생·체크/선택·스크롤·패널 상태를 보존한다.
- 글꼴·아이콘과 버튼·체크박스·기호·입력·정보 표·패널 경계·하단 면을 함께 다룬다. 문서 원문·코드·자막 등 콘텐츠 자체의 글꼴은 기존 역할을 유지한다.
- 명암 테마는 디자인과 별개이며 시스템 Light/Dark를 따른다. 고대비에서는 시스템 상태색과 포커스 식별성을 우선한다. 외부 글꼴은 라이선스와 함께 동봉하고 실행 중 CDN을 사용하지 않는다.
- 하단 높이 44, 기본 버튼 32×32, 텍스트 조작부 84×32와 A426의 공통 버튼 위치를 유지한다. A112 Back/Esc와 F11/F12의 패널 동작도 유지한다.
- 체크한 작업 대상·현재 선택·열린 콘텐츠 표시는 서로 다른 의미로 남긴다. hover/pressed/disabled/focus/mixed 상태를 확인한다.

### 실제 요소 연결 원칙

- 아이콘의 의미와 디자인 정의를 명시 입력으로 받는 같은 팩토리를 실제 UI와 미리보기에서 사용한다. 모듈마다 연결된 Shared 코드의 정적 상태를 공유 상태로 가정하지 않고 Core의 디자인 선택을 단일 출처로 삼는다. 미리보기와 팩토리 내부 도형은 전체 UI 갱신의 하위 탐색에서 제외한다.
- 현재 창의 실현된 요소와 새 창·가상화 컨테이너·팝업은 Loaded 때 연결하고 Unloaded·Closed에서 구독을 정리한다. 갱신은 UI 디스패처에서 수행하며 매 프레임 전체 시각 트리를 훑거나 데이터 항목을 전부 열거하지 않는다. 창을 닫을 때 분리된 요소도 정리할 수 있게 소유 루트를 기억한다.
- 실제로 로드된 요소에 뒤늦은 Unloaded가 오더라도 정상 정리를 먼저 수행한다. 같은 활성 창에 남은 요소에 한해 한 번 재연결을 예약하고, 실행 직전 세대·로드 상태·등록 루트·콘텐츠 제외 여부를 다시 확인한다. 창 종료나 루트 해제에서는 재연결하지 않는다.
- 이름 있는 FontIcon과 바인딩 대상은 같은 객체를 유지한다. 터미널 문자로 바꿀 때 원래 의미 글리프를 별도로 보관하고 외부 글리프 갱신·컨테이너 재활용을 반영한다. FontIcon 내부 글자의 서식은 소유 아이콘에 맡겨 문자 디자인에서 돌아올 때 이전 글꼴이 남지 않게 한다. 버튼 템플릿이 필요하면 초기 구성에만 설정하며 디자인 전환 때문에 모듈·콘텐츠를 옮겨 붙이지 않는다.
- 숨겨 만든 경로 표시줄의 아이콘, 일반 목록의 폴더·파일 아이콘, 새 Hardware 그래프·사양과 파일 메타 정보 글자는 생성 시점에 기존 디자인 수명 관리에 등록한다. Record 소스 템플릿은 같은 관리 setter를 가진 명시적 스타일을 사용한다. 실제 적용은 원래의 Loaded·등록 창·콘텐츠 제외 검증을 따르며, 진단 이벤트 구독에 기대어 제품 연결을 보완하지 않는다. 생성 등록을 위해 센서 갱신 주기나 사양 재생성 구조를 바꾸지 않는다.
- 체크·드롭다운·트리·슬라이더의 네이티브 입력·상태·포커스는 유지한다. 원래 템플릿 상태 대상을 제거하지 않고 필요한 표시 부분만 디자인 기호와 연결한다. 시스템 고대비에서는 재정의한 네이티브 상태 자원에도 시스템 색을 제공한다. 갤러리의 적용 카드 표식과 강조 외곽은 전체 디자인 갱신에서도 보존한다.
- 콘텐츠 제외 정보는 기존 의미 Tag를 덮어쓰지 않는 약한 역할 정보로 전달한다. 문서 편집·Markdown·가상 편집기·WebView·PDF·Office 페이지/본문·인쇄와 문서 텍스트 썸네일을 보호한다. 파일명·메타 정보·문서 도구막대는 UI로 남긴다. 녹음 상태의 빨간 표시와 그래프 의미색은 중립 팔레트로 덮지 않는다.
- 장식은 원래 요소의 외곽을 따르며 목록·패널의 원하는 크기를 늘리지 않는다. 여백이 있는 카드도 바깥 Border를 기준으로 그리고, 콘텐츠·입력 영역을 옮기지 않는다. 스크롤 손잡이·얇은 진행 채움·대기 회전은 네이티브 입력과 애니메이션을 유지하며 디자인 색·모서리·주변 조형을 적용한다.
- [A429](../../REQUIREMENTS.md#a429): 메뉴의 항목 사이·구분선·내부 여백은 연속된 배경으로 뒤 콘텐츠를 가린다. 컨트롤 배경 장식은 그 컨트롤의 직접 템플릿 루트에만 붙이며, 콘텐츠 안의 다른 버튼이나 부모 컨테이너를 대신 사용하지 않는다. 지원하는 장식 루트가 없는 기본·개별 스타일은 원래 배경을 유지한다.
- 크기·굵기는 직접 지정·스타일·네이티브 기본값과 부모 상속을 각각 구분해 한 번만 보정한다. 열린 파일 이름의 강조는 디자인의 기본 굵기 위에서도 구별하며, 새 창·늦게 만든 메뉴·재활용 항목에 누적 보정하지 않는다. 앨범아트의 검정 띠 위 흰 글자처럼 배경과 짝을 이룬 지역 대비색은 보존한다.

## 완료 기준

11개 선택·저장·재실행·기존 창/다중 창 갱신과 갤러리의 적용 표식을 검증한다. 전체 앱의 대표 모듈·메뉴·가상화 타일에서 디자인 누락과 한글 대체 글꼴, 밝고 어두운 테마·배율을 확인한다. 실제 화면 검수는 사용자에게 먼저 묻고 진행한다. 현재 구현·검수·배포 상태는 [HANDOVER](../../HANDOVER.md)에 갱신한다.

## A431 미리보기와 실제 화면 차이 진단

2026-11-23 사용자는 Folded paper 실제 탐색기와 Applied 카드 화면을 첨부하고 진단·원인 파악까지만 요청했다. 제품 코드는 변경하지 않았다. 두 원본과 해시·좌표별 색상은 `artifacts/a431-review/actual-paper.png`, `preview-paper.png`, `reference-measurements.json`에 보존했다. 읽기 전용 확인 당시 공식 v0.433.3 제품 커밋 `cb30bb8`, 저장 디자인 `paper`, UI 배율 200%였으며 이는 첨부 촬영 시점을 확정하는 근거는 아니다.

근본 원인은 **디자인 정의를 공유해도 화면을 조립하는 규칙은 두 벌**이라는 점이다. [DesignPreviewRoot](../../../src/KOTU.App/Appearance/DesignPreviewRoot.cs)는 실제 앱 컨트롤을 넣지 않고 [DesignPreviewRenderer](../../../src/KOTU.App/Appearance/DesignPreviewRenderer.cs)의 900×482 고정 예시를 Viewbox로 축소한다. 실제 앱은 기존 컨트롤·레이아웃을 보존하면서 LiveDesign으로 외형을 바꾼다. 같은 DesignCatalog·DesignSurface·아이콘 도형을 사용한다는 사실만으로 전체 결과가 같아지지 않는다.

| 항목 | 코드로 확정한 차이 |
|---|---|
| 좌우 패널 | Paper 미리보기는 Card(`#FFFDF6`)와 바깥 여백 8 DIP를 사용한다. 실제 패널은 Panel(`#E1D9C9`)을 사용하며 기존 도크 경계를 따른다. 첨부에서도 밝은 종이 패널과 더 어두운 전체 높이 패널로 구분된다. |
| 일반 타일 | 미선택·미체크 예시 타일은 Background(`#EEE9DF`), 실제 Card 역할 타일은 Card(`#FFFDF6`)를 쓴다. 색 정의가 달라진 것이 아니라 같은 정의에서 다른 역할을 선택한 것이다. [실제 적용](../../../src/KOTU.App/Appearance/LiveDesign.Appearance.cs) |
| 타일·화면 비율 | 예시는 타일 153×106과 3열·파일 6개를 고정한다. 실제 [ThumbnailExplorer](../../../src/KOTU.App/Controls/ThumbnailExplorer.xaml.cs)는 가용 폭/열 수로 폭을 정하고 높이를 폭+4 DIP로 계산한다. 실제 좌우 도크는 각각 25%이며 경로줄·정렬 도구 위치도 예시와 다르다. 배율을 같게 해도 이 구조 차이는 남는다. |
| 제목줄 | 예시는 Panel색의 제목줄을 직접 그리지만 실제 [TitleBarTheming](../../../src/KOTU.App/TitleBarTheming.cs)은 이전 사용자 결정에 따른 고정 브랜드색 `#15072E`를 사용한다. OS 강조색 문제로 판정하지 않는다. |
| 아이콘 색 | 예시는 팔레트 전경색을 명시한다. 실제 일반 폴더는 Foreground 없는 FontIcon이며 LiveDesign의 해당 경로는 기호·글꼴·크기만 바꾼다. 색 공급 경로가 다른 것은 확정이며 첨부의 검정 기호와 부합한다. 당시 검정 유효값을 공급한 정확한 상속·네이티브 상태는 이번 정적 진단에서 확정하지 않았다. |

긴 실제 폴더 트리와 빈 오른쪽 안내, 예시의 Locations·회의록 상세는 데이터·열린 파일 상태 차이다. 이 부분 자체를 스킨 적용 실패로 세지 않는다. Applied는 [선택 ID 일치](../../../src/KOTU.App/Appearance/DesignPicker.cs) 표식이며 화면 전체의 일치 판정이 아니다. 접힌 모서리는 두 첨부에서 보이고, 코드·설정도 Paper 선택을 가리킨다. 다른 10개 디자인도 별도 예시 구조를 공유하지만 이번 첨부 진단에서 차이 크기를 실측한 대상은 Folded paper뿐이다.

기존 아이콘 시험은 공통 도형, 디자인 검수기는 팔레트 갱신·미리보기 격리·기존 치수 보존 등을 검사한다. 미리보기 전체와 실제 탐색기의 화면 동등성을 검사한 것으로 볼 수 없으며, 이전 11종 관측도 이 대조의 통과 근거로 확대하지 않는다. 이번 결론은 첨부 색상 측정·코드 대조·독립 검토에 근거하고 새 실화면 조작은 없었다.

### 사용성을 보존한 대표 검수

진단 후 사용자는 기존에 촘촘하게 조정한 트리 줄 간격 등 사용성을 유지할 필요와, 미리보기의 미감이 여백에 의존할 가능성을 함께 제기했다. 11종을 일괄 재설계하기 전에 Folded paper 한 종류의 실제 검수본으로 평가하는 제안에 “그렇게 해보자”라고 동의했다.

첫 검수는 트리 22-DIP 기준·들여쓰기·이름/펼침 정렬, 기본 버튼 32×32·하단 44 DIP, 패널 비율과 타일 크기 계산 및 입력 경로를 유지한다. Paper의 밝은 종이 패널·중앙 바탕과 어울리는 타일·기호색을 현재 배치에 적용해 본다. 비교자료는 같은 창 크기·배율·폴더 목록을 사용하는 실제 검수 앱의 전후 화면으로 만든다. 한 화면의 폴더 수·긴 이름 잘림·선택과 체크 구별·펼침/접기·키보드 이동을 비교하며, 기존 브랜드 제목줄은 유지한다.

범위는 공식 설치와 분리된 로컬 검수본이다. 현재 제품 코드·나머지 10종을 먼저 바꾸거나 전체 재설계·공식 배포까지 승인된 것으로 해석하지 않는다. 결과를 본 뒤 사용자가 확대 여부를 정한다.
