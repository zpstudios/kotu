# A391 녹화·녹음 저장 기본 위치

## 구현

- 영상은 `Environment.SpecialFolder.MyVideos` 아래 `KOTU`, 녹음은 `MyMusic` 아래 `KOTU`를 초기 저장 위치로 사용한다. Windows의 알려진 폴더 조회이므로 사용자 라이브러리 이동 설정을 따르며, 알려진 폴더가 비어 있거나 사용자 설정 경로가 잘못되면 다른 경로로 대체하지 않는다.
- 메인 화면의 Save folder에는 현재 모드의 위치를 표시하고 Change folder로 바꿀 수 있다. 사용자 위치는 `record.videoFolder`와 `record.audioFolder`에 별도로 저장한다. 선택 취소와 실패는 이전 위치를 유지한다. 설정 저장 실패 시 메모리 설정도 이전 값으로 복구한다.
- `InitializeFoldersAsync`는 워커 초기화 훅이다. 기본 위치 조회, 설정 복원, Directory.CreateDirectory, 쓰기/삭제 권한 탐침은 모두 모듈 워커에서 수행한다. 임시 탐침은 DeleteOnClose로 닫는 즉시 삭제한다. 영상/녹음 위치를 각각 준비하므로 한쪽 실패가 다른 모드를 막지 않는다.
- Start는 초기화/폴더 선택이 끝나고 현재 위치가 유효할 때만 활성화된다. 시작 시 모드·소스·마이크·믹스·폴더를 먼저 캡처하고, 셀렉터를 잠근다. 워커가 폴더를 재검사하고 타임스탬프+GUID 파일명을 생성한다. 시작할 때 SavePicker를 열거나 빈 최종 파일을 만들지 않는다.
- 전체 GUID는 동시 세션 충돌 확률을 줄이는 목적으로 유지한다. 이름만 생성하는 단계의 경합을 전제로 성공 공개는 `Publish(..., overwrite: false)`를 사용한다. 실제 충돌이 생기면 기존 파일을 보존하고 새 임시 파일의 회수 위치를 표시한다.
- 기존 형제 임시 파일, 폐기, 정상 완료 후 공개, 오류 시 부분 결과 보관 계약을 유지한다. 기존 명시 목적지용 Publish 호출은 기본 overwrite=true 계약을 유지한다.
- 새 FolderPicker는 저장소 ArchiveView의 FileTypeFilter/InitializeWithWindow/PickSingleFolderAsync 선례를 따른다. 선택 및 초기화의 늦은 결과는 `_disposed` 검사로 무시한다. 워커에는 수명 토큰을 전달하고 폴더 준비 뒤/네이티브 시작 전 취소를 재확인한다.
- Open folder는 기존대로 마지막 정상 결과 또는 회수 가능한 임시 결과의 상위 폴더를 열며, 저장 위치 선택 버튼과 구분된다.

## 검증

- Record 모듈 Release/x64 빌드: TreatWarningsAsErrors=true, 경고 0개/오류 0개.
- RecordingOutputTests: 12/12 통과(기존 4개 + 신규 8개).
- 신규 검증: 두 모드 기본 폴더 생성/반복 준비/탐침 정리, 사용자 위치의 알려진 폴더 미조회, 파일을 폴더로 지정했을 때 명시 실패/기존 파일 보존, 알려진 폴더 없음/상대 경로 거부, 동일 타임스탬프 100개 이름의 모드별 확장자/중복 없음/빈 파일 미생성, 공개 경합 시 기존 파일과 임시 결과 보존, 새 목적지 정상 공개.
- diff 공백 검사 및 새 한글 주석의 이스케이프 검사 통과.

## 한계 및 화면 확인

GUI와 실제 녹화 장치는 실행하지 않았다. 리디렉션된 동영상/음악 라이브러리, FolderPicker 취소와 모드 전환, 사용자 폴더 설정 재실행 복원, 실제 ACL 거부, 폴더 선택/초기화 도중 뷰 종료, 정상 녹화·녹음/폐기/부분 파일 회수는 실기기 확인이 필요하다. 단위 테스트의 생성 오류는 기존 파일을 폴더 경로로 쓰는 재현 가능한 실패로 검증했으며 ACL 구성을 변경하지 않았다.

후속 A388~A390의 선택지/장치 목록 UI가 바뀌어도 `InitializeFoldersAsync`와 현재 모드별 폴더, 시작 전 스냅샷, `_choosingFolder` 잠금, 수명 검사 및 비덮어쓰기 공개 계약을 유지해야 한다.
