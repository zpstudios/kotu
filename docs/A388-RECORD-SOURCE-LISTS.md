# A388 녹화 소스 목록과 실시간 변경 반영

## 구현 범위

기존 Screen recording/Microphone recording 모드를 화면의 단일 선택 ListView로 표시한다.
화면/창, 시스템 출력, 마이크도 별도의 펼쳐진 선택 목록이다. 화면/창 목록은 `Screen:`/`Window:`
접두사로 구분하고 긴 목록은 영역 안에서 스크롤한다. 모드·소스 드롭다운은 제거했다.
기존 단일 화면/창 MP4 및 단일 마이크 WAV 범위는 유지하며 오디오 전용 시스템 믹스는 추가하지 않았다.

화면 녹화의 시스템 음원과 마이크는 각각 명시적 체크박스로 포함 여부를 고른다.
시스템 음원을 포함하면 선택한 활성 Render endpoint ID만 전달한다. 기본 출력으로 암묵적으로
되돌아가지 않는다. 둘 다 해제하면 `IsAudioEnabled=false`이고 추가 음원 목록도 비워 무음 영상이다.
마이크만 포함하면 마이크 단독 음원이며 두 음원을 포함하면 기존 70% 헤드룸을 적용한다.
음원 선택/비선택에 관한 설명을 화면에 표시한다. 녹음 모드는 선택 마이크가 필수다.

일반 ListView 단일 선택/스크롤과 Checked/Unchecked 이벤트는 기존 WinUI 컨트롤 조합이다.
ListView의 Label `DisplayMemberPath` 지정은 저장소 내 신규 사용으로 빌드에서 API 실재를 확인했으며,
실제 강조 표시와 키보드 접근은 아직 화면 확인하지 않았다.

## 선택 계약

| 상황 | 처리 |
|---|---|
| 최초 성공 관측, 저장된 ID 없음 | 기본 오디오 장치 또는 첫 항목을 초기 선택 |
| 저장된 ID가 현재 목록에 없음 | 미선택 유지, 다른 기본 장치로 대체하지 않음 |
| 기본 장치/제목/목록 순서 변경 | 안정 ID로 선택 보존, 변경된 행만 갱신 |
| 선택된 항목 제거 | ID 기억을 보존하되 현재 목록에서는 미선택 |
| 같은 ID 재등장 | 같은 소스로 선택 복원 |
| 녹화 중 목록 변경 | 목록을 갱신하되 선택·모드·음원 포함 여부는 잠금 |
| 활성 소스가 성공 관측에서 사라짐 | Stop/save, 이유 및 정상 결과/부분 파일 위치 표시 |
| 한 범주의 열거 실패 | 해당 이전 목록 유지, 별도 소스 상태에 오류, 소실로 판단하지 않음 |
| 관측 시작 후 새 소스 선택/녹화 시작 | 옛 관측의 선택과 활성 선택을 비교; 불일치 시 소실 판단을 건너뛰고 즉시 새 관측 요청 |

화면은 display device name, 창은 HWND+PID, 오디오는 endpoint ID가 식별자다.
창 제목 변경은 다른 창으로 보지 않으며 PID가 달라진 같은 HWND는 다른 창이다.
관측 범위는 화면 32개/창 200개/각 오디오 64개다. 관측 시작 시 선택된 소스가 현재 사용 가능하면
상한 내부에 반드시 남기므로 단순한 순서·기본 장치 변경 때문에 소실로 오판하지 않는다.

`Recorder.GetWindows`가 최소화/숨긴 창을 제외하더라도 선택된 HWND가 같은 PID에 속하면
현재 선택을 목록에 남긴다. 새 `IsWindow`/`GetWindowThreadProcessId` user32 호출은 워커에서만
수행한다. 녹화 시작 직전에는 기존 네이티브 열거와 최소화 여부를 다시 검사해 복원된 창만 시작한다.
이 창 생존 판정은 HWND+PID 기준이며 같은 프로세스 내부의 드문 HWND 재사용까지 구분하지는 않는다.

## 스레드·수명

| 작업 | 실행 위치/방어 |
|---|---|
| 2초 폴링 | ThreadPool Timer에서 발견 작업 예약만; UI 타이머 없음 |
| 화면/창/NAudio 열거·정렬·창 생존 확인 | 별도 BelowNormal `KOTU record source discovery` ModuleWorker |
| 작업 예약/결과 적용 | 원자적 pending gate로 관측+대기 UI 반영 전체에 최대 1개 |
| 목록 반영 | UI ObservableCollection 차이만 적용; 동일 행 참조·ItemsSource 보존 |
| 네이티브 Start/Stop/Dispose, 저장 설정/파일 | 기존 `KOTU record worker`; 발견 큐와 별개 |
| 시작 중 소실 | 불변 활성 선택을 시작 전에 보관; 발견된 이유를 기록하고 세션 획득 후 Stop/save |
| 녹화 완료 | Completion 후 네이티브 해제/공개; 소실 이유를 성공/오류 메시지에 유지 |
| Unloaded | disposed·seq 증가, 폴링 Timer 종료, 발견 큐 종료, 수명 취소; 늦은 UI 반영 무시 |

발견 워커에는 UI 객체를 넘기지 않고 HWND 값과 불변 선택만 전달한다.
타이머·워커 단계에서 disposed/cancellation/seq를 확인하며 UI 콜백에서도 다시 검사한다.
관측 완료 후 디스패치 대기까지 pending gate를 유지해 느린 UI에 예약이 쌓이지 않는다.
비동기 관측 예외를 모두 관측해 표시하며 정상 폴링은 녹화 상태/저장 오류 메시지를 덮지 않는다.
폴링 중에는 선택기를 반복 잠그지 않는다. 초기화·폴더 선택·녹화 중의 기존 잠금은 유지한다.

NAudio의 기존 MMDeviceEnumerator/활성 장치 열거/GetDevice API를 사용했다.
MMDevice.DataFlow는 로컬 2.2.1 XML 메타데이터에서 확인했고 Start 직전에 Active+Render/Capture를
검사한다. ScreenRecorderLib 7.0.1의 AudioSources 목록과 IsAudioEnabled 기존 API로 명시 음원을 구성한다.
네이티브 열거 자체의 시한은 추가하지 않았다. 정지 큐와 분리돼 발견이 걸려도 Stop이 그 뒤에
대기하지 않지만, 걸린 발견 호출이 끝날 때까지 소스 갱신/해당 워커 종료는 지연될 수 있다.

## A391 및 후속 항목

기본 폴더 워커 초기화, 모드별 사용자 폴더, 시작 전 폴더 스냅샷과 재검사, 타임스탬프+GUID 파일명,
형제 임시 파일, 비덮어쓰기 공개, 취소/부분 파일 회수는 보존했다. 폴더 선택기와 초기화가 소스
목록 갱신과 겹쳐도 현재 모드와 폴더 선택 잠금을 변경하지 않는다.

A389의 하단 버튼 배치와 A390의 녹화 표식은 이번에 변경하지 않았다.
후속 상태 UI는 `_activeSelection`, `_sourceLostReason` 및 실제 `_session` 상태를 사용할 수 있다.
