# 내장 탐색기 + 오버레이 UX 계획 (사용자 요청 2026-08-06 → v0.25.0 구현됨)

구현 전 사용자 확정 사항(2026-08-06):

- 탐색기 필터: **폴더 + 담당 확장자만** 표시
- 적용 모듈: 압축·비디오(음악 포함)·**이미지 포함** (문서 모듈은 생기면 적용)
- Ctrl 2연타 고정 해제: **Ctrl 2연타 재입력**으로 토글

구현 구조(v0.25.0): 셸 소유 방식 — 모듈 간 의존 규칙(모듈은 Core만 참조)을 지키기 위해
탐색기(ExplorerPane)·오버레이 UI는 App(MainWindow)이 소유하고, 모듈은 Core 계약 두 개만 구현한다.
IContentStateSource(파일 열림 알림 — 뷰 내부 열기도 셸과 동기화),
IContentInfoProvider(Ctrl 정보 오버레이 내용 — 비디오=미디어 정보, 이미지=EXIF; 미구현 모듈은 셸이 파일 기본 정보로 대체).

## 1. 빈 상태 = 탐색기

압축·문서(예정)·음악·비디오 모듈이 **아무 콘텐츠도 로딩하지 않은 기본 상태**일 때,
화면 중앙에 파일 탐색기를 표시한다.

- 첫 시작 위치: **바탕화면(Desktop)**
- 레이아웃: 중앙 영역에서
  - 좌측 70%: 윈도우 바탕화면처럼 **썸네일 방식 아이콘 그리드**
  - 우측 30%: **리스트 형태** 표시
- (해석) 모듈별로 담당 확장자 필터를 적용할지는 구현 전 확인 필요.

## 2. 콘텐츠 로딩 후 오버레이

콘텐츠가 로딩되면 콘텐츠가 화면 중앙에 표시되고:

- **Alt 키 홀드**: 우측 30% 리스트(탐색기 리스트 뷰)가 나타나고, 키를 떼면 사라짐.
- **Ctrl 키 홀드**: 해당 콘텐츠의 정보(동영상=미디어 정보, 사진=EXIF 등)가
  화면 **좌측 오버레이**로 키를 누르는 동안만 표시.
- **Ctrl 2연타**: 좌측 정보 오버레이를 **고정**(다시 해제할 토글 방법은 구현 시 확정 — 재연타?).

## 3. 구현 메모 (착수 시 검토)

- 탐색기 공용 컴포넌트로 만들어 각 모듈 빈 상태에 주입 (Core 계약 또는 App 공용 컨트롤).
- 썸네일: Windows.Storage.FileProperties.GetThumbnailAsync 활용 가능.
- 키 홀드 감지: KeyDown/KeyUp (KeyboardAccelerator는 홀드에 부적합). 창 포커스 문제 주의.
- EXIF: Windows.Graphics.Imaging.BitmapDecoder 속성, 미디어 정보: libvlc Media.Parse.
- Alt 키는 시스템 메뉴 활성화와 충돌 가능 — 실기기 검증 필요.
