# 구조 개선 작업 브랜치

2026-09-07 · v0.353.0 · A356 · `codex/architecture-document-session`

사용자 지시: 기본 브랜치 밖에서 구조 변경을 시작하고 커밋·푸시하며, GitHub에서 실행본을
내려받아 시험할 수 있도록 한다. 정합성 검사를 포함한다. 현재 기본 브랜치는 `master`다.

## 이번 단계의 경계

기존 셸·모듈 구조는 유지한다. 첫 단계로 문서의 저장 기준·저장 작업 식별자·종료 가능 판정을
WinUI 비의존 `KOTU.DocumentModel`로 옮긴다. 이 프로젝트는 패키지와 다른 프로젝트에 의존하지 않는다.
`DocumentSession`은 뷰 소유 스레드에서 사용하며 디스크 I/O를 하지 않는다.
`DocumentFileStore`는 기존 문서 워커에서 실행한다. 다이얼로그·인코딩 변환·더티 표시의
디바운스·렌더링은 뷰가 담당한다. 전체 문서 상태를 옮긴 단계로 해석하면 안 된다.

## 반드시 유지할 계약

| 조건 | 기대 결과 | 검증 |
|---|---|---|
| 저장 도중 추가 입력 | 저장한 스냅샷만 기준으로 반영, 남은 입력이 있으면 닫기 거절 | 모델 테스트 + 뷰 연결 정독 |
| 저장 중 undo로 이전 기준과 같아짐 | 진행 중 저장 자체가 종료 가드를 유지 | 모델 테스트 + HasUnsavedChanges 연결 정독 |
| 다른 콘텐츠로 교체 후 이전 저장 완료 | 작업 식별자가 달라 새 기준·파일명을 덮지 않음 | 모델 테스트 + CommitSave 연결 정독 |
| 다른 창의 저장 작업 | 현재 세션에 반영 불가 | 모델 테스트 |
| 저장 취소·실패 | 원래 기준 유지, 다시 저장 가능 | 모델 테스트 |
| 파일 교체 실패 | 원본 유지, 임시 파일 정리 | Windows 파일 잠금 테스트 |
| UTF-16 BOM·줄바꿈 바이트 | 전달받은 바이트를 그대로 저장 | 파일 테스트 |
| 프로젝트 참조 | 누락·순환 없음, 모델 UI 비의존 유지 | eng/Test-Architecture.ps1 |
| 배포 파일 | PRI·엔진·샘플·새 DLL 포함, 실행 직후 종료하지 않음 | 브랜치 빌드 |

저장은 같은 폴더의 임시 파일에 기록·flush·검증 후 기존 파일을 교체한다. 교체가 지원되지 않거나
실패하면 직접 덮어쓰기로 후퇴하지 않는다. 읽기 전용 파일과 reparse point는 거절한다.
검증은 전원 장애 시 장치의 내구성, 모든 네트워크/클라우드 파일시스템의 동작, 또는 외부 프로그램과의
완전한 동시 쓰기 격리를 보장하지 않는다. 하드링크의 다른 이름까지 함께 갱신하는 저장 방식도 아니다.
기존 수정 시각·크기 검사는 유지하며 외부 변경 검사와 실제 교체 사이의 경쟁 조건은 후속 과제다.

## 브랜치 실행본

GitHub → Actions → build → 해당 브랜치/커밋의 성공한 실행 → Artifacts에서
`KOTU-win-x64-<커밋 SHA>`를 다운로드한다. 14일 보관한다. ZIP 전체를 풀고 `KOTU.exe`를 실행한다.
테스트 성공 후에만 publish·패키지 검사·시작 검사·실행본 업로드를 수행한다. 실패한 테스트 결과도
별도 `test-results-...` 아티팩트로 보관한다. 공식 Release나 설치 프로그램은 만들지 않는다.

기존 KOTU를 완전히 종료한 뒤 시험한다. 현재 앱은 같은 단일 인스턴스 키와 사용자 설정·파일 연결을
사용한다. 설치판과 동시에 격리 실행되는 샌드박스가 아니다. `%AppData%/KOTU`를 백업하고 시험할 것.
시작 검사는 프로세스 생존과 시작 오류 로그를 확인하는 것으로, 화면 조작의 완주 검증은 아니다.

수동 확인: 텍스트·Markdown·HTML의 편집 저장, 새 텍스트 첫 저장, 저장 확인 취소, 문서→PDF 전환,
All Readable에서 문서→다른 모듈 전환, 저장 후 닫기, 읽기 전용·대용량 잘림 문서의 저장 차단.
느린 저장 중 추가 입력 시 창이 남고 더티 표시가 유지되는지도 확인한다.
