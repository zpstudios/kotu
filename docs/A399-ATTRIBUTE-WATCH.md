# A399-a — 속성 감시와 갱신 병합

2026-10-14, v0.393.0. A399-b 원문 접근 보호는 유지한다. 이 배치는 속성 통지 누락과
UI 이벤트 큐/재조회 중첩을 고친다. 실제 OneDrive 제보 원인 확정이나 제공자 재시도 완료가 아니다.

## 구현과 검수

- `FolderWatch`가 FileName/DirectoryName/LastWrite/Size에 Attributes를 더한다.
  생성·OS 핸들 해제는 워커에서 수행하고, UI 해제 시 통지를 먼저 닫는다.
- `DebouncedWatchEvents`는 워커 타이머로 마지막 이벤트 뒤 400ms를 유지한다.
  UI 큐에는 최대 한 콜백만 올리고, 밀린 콜백을 소비할 때도 정숙 시간을 재확인한다.
  일반 통지/오류를 같은 세대로 묶으며 오류는 한 번의 감시 재생성과 재조회로 합친다.
- `ExplorerPane`의 실행 가드는 경로 확인부터 전체 열거·목록 반영까지 유지한다.
  실행 중 요청은 bool 하나로 보류한다. 같은 폴더의 자동 갱신은 감시자를 교체하지 않아
  열거 중 변경을 잃지 않는다. 명시 Refresh·폴더 전환은 기존 전체 재조회 계약을 유지한다.
- 이름변경 중에는 재조회를 시작하지 않고, 열거 도중 편집이 시작되면 결과 반영도 보류한다.
  편집 종료 후 보류분을 한 번 소화한다. 언로드 시 load 세대도 올려 재로드 뒤 옛 결과를 막는다.
- 최대 함정은 폐기된 감시자의 통지와 기존 열거 완료가 새 폴더의 보류 상태를 덮는 것이다.
  감시 세대·load 세대·폴더·수명을 대조하고, 실행 가드는 옛 작업의 finally까지 유지한다.

## 자동 검증

- 최종 전체 Release/x64 빌드 0경고·0오류, 전체 **609/609**, 실패0·skip0.
  구조20프로젝트·릴리스 게이트7개 통과, App self-contained publish 성공.
- 신규 감시 시험10개: 100회 burst, 밀린 UI 큐의 상한/정숙 재확인, 오류 병합,
  해제 뒤 늦은 콜백, 큐 종료, 소비 중 새 이벤트, 느린 재조회·편집, 실행 중 재대상,
  느린 미리보기 100세대, 실제 로컬 속성 변경 및 Offline 비트 스냅샷 왕복.
- 로컬 임시 NTFS 파일의 Offline 비트만 켰다 끄는 시험에서 길이/수정시각 불변인 채
  새 Entry의 IsPlaceholder가 false→true→false로 반영됐다. 이는 합성 메타데이터 시험이며
  실제 클라우드 공급자/WinUI 배지 관측이 아니다. 사용자 파일의 속성은 바꾸지 않았다.
- 느린 미리보기 시험은 제품 `ModuleWorkerPool`/`CancellableBatch`를 사용한다.
  초기3개를 지연한 채 100세대를 예약하면 중간 세대의 워커 실행0, 초기3+최신3=6회 실행,
  최신 결과3회 반영이다. WinRT 네이티브 작업이 취소/timeout 뒤 영구 잔류하는 조건은 시험하지 않았다.
- 기존 조사 프로브도 현재 `FolderWatch.Filters`를 읽도록 갱신했다. Hidden 속성만 바꾼
  3회 모두 통지1회, 내용 변경 대조군 통과, 오류0. 길이/수정시각 불변.

근거: `artifacts/a399-a/final-build.log`, `final-tests.log`, `final-tests/*.trx`,
`publish.log`, `attribute-probe.json`. 로컬 testhost 연결이 90초 뒤 실패한 첫 시도는
성공으로 세지 않았다. 동일 시험을 승인된 제한 밖에서 실행해 통과했다.
