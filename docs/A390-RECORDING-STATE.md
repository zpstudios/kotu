# A390 실제 녹화·녹음 상태 표시

## 변경

- 중앙의 작은 상태 배너와 하단 줄에 붉은 점, Recording screen/Recording microphone, 경과 시간, 현재 캡처 소스 이름을 표시한다. 색 외에도 상태 텍스트를 함께 쓰며 큰 시계는 추가하지 않는다. 하단은 기존 네 조작 버튼/Star 상태 열 구조를 유지한다. 긴 내용은 말줄임하고 전체 툴팁/접근성 이름으로 제공한다.
- 시작 버튼을 누를 때 화면/창, 선택한 시스템 출력, 선택한 마이크의 Label을 문자열로 고정한다. 이후 장치 열거가 같은 ID의 이름을 바꾸거나 장치가 사라져도 실제 캡처의 소스 표시를 다른 목록 값으로 바꾸지 않는다. 저장/실패 뒤에도 마지막 캡처 소스를 표시한다.
- `RecordingPresentation`은 XAML 비의존 순수 표시 규칙이다. Ready, Starting, Active, Stopping, Saving, Finished, Error를 받고 실제 세션 IsRecording/완료 스냅샷으로 Active만 확정한다. _busy를 녹화 중으로 해석하지 않는다.
- 폴더 검사/네이티브 시작 대기는 Starting이다. 실제 세션이 캡처 중이라고 보고한 다음에만 붉은 점과 활성 녹화 문구를 표시한다. 한 번 캡처한 뒤 네이티브 캡처가 멈추면 Starting으로 되돌아가지 않고 Saving을 표시한다.
- 정지 요청은 즉시 Stopping으로 바꾸고 붉은 점을 제거한다. 네이티브 Completion을 받은 즉시 Saving으로 바꾼다. 공개 성공/폐기는 Finished, 시작/녹화/공개 실패는 Error가 된다. 기존 상세 오류·부분 파일 회수 위치 및 소스 소실 메시지는 유지한다.
- 배너·하단·트레이는 같은 cached presentation을 사용한다. 트레이는 실제 캡처 중에만 빨간 VRC/ARC(영상/오디오), 다른 단계는 중립색 PRE/STP/SAV/END/ERR를 쓴다. 최초 Ready는 기존 REC 모듈 유휴 표시다.

## 스레드·수명·경합 검수

- 기존 ThreadPool 250ms 타이머가 원자적 Elapsed/IsRecording 및 Completion 상태만 읽는다. 완성 스냅샷을 UI에 반영한다. 캡처 루프/파일 I/O/작업자 대기나 깜빡임 타이머를 UI에 추가하지 않았다.
- queued tick은 뷰 미해제, 같은 세션, Active 단계인지 확인한다. UI 대기 중 Completion이 된 경우 Task.IsCompleted를 비블로킹으로 재확인해 이전 활성 스냅샷을 쓰지 않는다. Saving/Finished/Error를 늦은 tick이 덮어쓰지 않는다.
- 정지 작업의 늦은 오류는 같은 세션/Stopping/미완료일 때만 Active 시도로 복귀시킨다. 이미 저장/완료된 상태를 되돌리지 않는다. 실제 캡처 표시 복귀는 다음 타이머 스냅샷에 따른다.
- 네이티브 최종 경과 시간은 워커에서 Dispose 전에 읽어 완료 결과와 함께 UI로 반환한다. 공개 오류 시에는 마지막 확인된 경과 시간을 유지한다. 새 시도는 경과 시간과 캡처 관측 여부를 초기화한다.
- 장치 감시는 별도 discovery 표시만 갱신하며 상태 배너를 덮어쓰지 않는다. 소스 소실 시 기존 안전 정지/저장 경로를 그대로 사용한다. 해제 후에는 표시/트레이 갱신을 하지 않는다.

## 검증과 한계

- Record 모듈 Release/x64 빌드: TreatWarningsAsErrors=true, 경고 0개/오류 0개.
- RecordingPresentationTests 11/11 통과: 시작 전/네이티브 대기 중 활성 오표시 방지, 실제 영상/녹음의 모드·시간·소스·트레이 색, 정지/저장/완료/실패의 늦은 녹화 스냅샷 우선순위, 완료 경합, 네이티브 finishing, 새 시도 초기화, 유휴 상태.
- 프로젝트 XML 파싱, diff 공백 및 실제 한글 주석의 이스케이프 검사 통과.
- GUI/실제 장치 녹화는 미실행이다. 배너/하단/트레이의 실제 가독성·테마·좁은 폭·접근성, 화면 및 마이크 시작 지연, 빠른 정지/실패/소스 소실·폐기·종료 전이, 녹화 타이머의 최종 시간은 실기기 확인이 필요하다. 실제 캡처 표식은 기존 250ms 스냅샷 주기/디스패처 지연 범위에서 반영된다.
