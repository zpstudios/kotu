# KOTU v0.371.0 실기기 QA 보고서

2026-10-02 KST, 실행 중인 설치본을 직접 조작했다. 주요 기능은 아래 표본에서 정상 동작했으나,
All Readable 전환 중 프로세스 강제 종료 1회, PDF Contain 하단 잘림, Alt+Enter 안내 불일치를 확인했다.
발견 항목은 A380~A382에 등록했다. 이번 요청은 테스트이므로 제품 코드는 수정하지 않았다.

## 3. A380 All Readable 전환 중 강제 종료

최초 실행에서 Document·Archive·Audio·Video·Image·All Readable을 순차 시험한 뒤,
All Readable에서 PNG를 열고 MP3로 바꿨다. MP3를 일시정지하고 F11로 좌 목록을 열어
`invalid.zip`을 더블클릭하자 열린 두 KOTU 창과 프로세스가 함께 사라졌다.

Windows Application Error 이벤트 1000은 **2026-10-02 11:41:59 KST**에
KOTU.exe **0.371.0.0**, Microsoft.UI.Xaml.dll **3.1.8.0**, 예외 **0xc000027b**,
오프셋 **0x3a7515**를 기록했다. 보고서 ID는
`4002cd59-c31e-4493-a53d-1e473ad133a3`이다.
이벤트는 `artifacts/qa-20261002/crash-events.json`에 저장했다.

대조 시험:

- 단독 Archive에서 같은 손상 ZIP은 정상적으로 오류를 표시하고 복구됐다.
- 재시작 후 All Readable 빈 화면에서 같은 ZIP을 열어도 정상 복구됐다.
- 이어 MP3를 열고 일시정지→F11→같은 ZIP 전환을 한 번 더 시험했으나 종료는 반복되지 않았다.

따라서 실제 종료 관측은 확정이지만, 손상 ZIP 또는 오디오 교체가 원인이라고 단정하지 않는다.
전체 선행 전환 이력·다중 창·완료 Jobs·비동기 수명/레이아웃을 함께 조사해야 한다.
이벤트의 XAML 모듈명만으로 구체적인 원인이나 기존 A352와의 동일성을 확정할 수 없다.

## 4. A381 PDF Contain 하단 잘림

시험 PDF는 612×792pt 3페이지이며, 각 페이지 안쪽 12pt에 파란 사각 테두리를 넣었다.
위 환경에서 Document로 열면 첫 페이지 위·좌·우 테두리는 보이지만 아래 테두리는
하단 바 아래로 내려가 보이지 않는다. Fit width 뒤 Contain을 다시 선택해도 같았고,
앱 재시작 후 All Readable에서 열어도 재현됐다. 조금 스크롤하면 아래 테두리가 나타난다.
Fit width의 좌우 정렬은 정상이다.

기대 결과는 Contain이 하단 바를 제외한 실제 가시 영역에 페이지 전체를 넣는 것이다.
현행 소스의 Fit 산식은 ScrollViewer.ViewportHeight를 쓰며, XAML 주석은 하단 바가
콘텐츠 위 오버레이임을 명시한다. **가시 높이와 뷰포트 높이의 차이가 조사 후보**이며,
원인은 아직 확정하지 않았다. 다른 창 크기·UI 배율에서의 발생 범위도 미확인이다.

증거: `artifacts/qa-20261002/pdf-contain-0.png`, 시험 자료:
`artifacts/qa-20261002/qa-three-pages.pdf`.

## 5. A382 Alt Enter 안내와 편집기 동작 불일치

USER-GUIDE.md §1.1은 Alt+Enter가 텍스트 입력 중에도 전체 화면에 직행한다고 설명한다.
실행본의 Markdown 편집기에서 입력하면 전체 화면으로 바뀌지 않고 개행이 생긴다.
Undo로 입력을 복원했다. 전체 화면 버튼과 Esc 왕복은 정상이다.

현행 저장소의 OnShellAltEnter도 IsTextInputFocused일 때 반환하도록 되어 있다.
이 기록은 안내와 동작의 차이를 등록한 것이다. 단축키 사양의 최종 결정이나 제품 코드 변경은
이번 테스트에서 하지 않았다. 테스트 도구의 Alt 키 전달 차이를 완전히 배제한 추가 검증은 미실행이다.
