# A401 — 큰 문서 성능 조사와 다음 구현 배치

조사일: 2026-10-13. 소스 기준: `29b5638`, master, 제품 v0.391.0.
상태: **조사·합성 모델 기준선 완료. 제품 수정 및 실제 문서 스크롤 성능 개선은 미실시.**

## 2026-10-20 추가 제보 — 연속 Enter의 새 줄 표시 지연

사용자는 큰 문서에서 Enter를 여러 번 연달아 누르면 새 줄이 추가되어 보이는 속도가 매우 느려지며,
큰 문서 스크롤 지연과 증상이 유사하다고 했다. 새 제보의 파일 종류·크기·줄 수·입력 위치·앱 버전·
검색 상태는 미제공이다. 이전 TXT/코드 답변은 우선 조사 대상의 근거이고 이번 입력의 조건을 확정하지 않는다.
**증상 유사성은 동일 원인의 증거가 아니며, 이번 제보는 아직 실행 재현하거나 계측하지 않았다.**

후속 A401-b/c 배치 정의 전에 다음 조건을 기존 스크롤 행렬에 추가한다.

- 같은 문서의 머리/중간/끝에서 단발·연속 Enter를 일반 문자·Backspace 및 변경 없는 스크롤과 비교한다.
  키 입력부터 본문 변경, 캐럿/새 줄의 화면 표시까지와 입력 종료 후 밀린 표시의 해소를 구분한다.
- 장식 on/off, 줄 길이·줄 수·Wrap, 창/배율을 고정한 대조를 한다. 편집별 스냅샷·색인·변경량 추적,
  캐럿 자동 스크롤·TextBox 레이아웃은 후보이고 병목 확정이 아니다. NoWrap의 기존 본문 소실 한계는 유지한다.
- A396 이후의 검색어 없음/활성 검색을 나눠 본다. 오래된 계측 결과를 현재 검색 동작의 입력 지연 증거로
  재사용하거나 검색 추가를 원인으로 단정하지 않는다.
- 입력 수와 실제 줄 증가량·캐럿 위치, Undo/Redo·선택·검색 결과 갱신·더티 복귀·줄바꿈/인코딩·저장 보호를
  함께 검증한다. 잘림/읽기 전용 문서에 편집을 허용해서는 안 된다.

이는 재현 행렬의 보강이며 새로운 제품 구현 배치의 착수나 성능 개선 완료를 뜻하지 않는다.
이하 조사 수치와 소스 행 번호는 각 절에 적힌 과거 기준을 유지한다.

## 1. 결론과 증거 범위

- 사용자는 큰 문서를 열고 스크롤할 때 매우 느리다고 했고, 후속 답변으로 **“TXT 또는 코드 파일”**을
  지목했다. 파일 크기·확장자·줄 모양·창 크기는 아직 없다. 화면 밖까지 그린다는 설명은 사용자 추정이다.
- 우선 대상은 TXT/코드가 연결되는 `DocumentView`의 **WinUI TextBox + 자동 줄바꿈 + 장식 좌표 측정**이다.
  이 세 요소의 비용을 분리할 UI 계측이 아직 없으므로 어느 하나를 확정 원인으로 선언하지 않는다.
- 전체 텍스트 복사와 논리 줄 전수 스캔은 **이미 편집별 스냅샷/색인으로 공유**한다. 같은 텍스트를
  스크롤하는 동안 매 이벤트마다 새 전문 복사·새 줄 색인이 생긴다는 가설은 현 소스와 맞지 않는다.
- 1,048,576자 상한과 장식 자동 해제는 이미 있다. **정확히 상한인 문서는 장식이 살아 있고**, 상한을
  넘은 문서는 잘린 앞부분을 같은 TextBox에 넣는다. 따라서 기존 상한을 해결책으로 다시 제시하지 않는다.
- 편집기 교체·전체 문서 가상화는 이번 조사에서 결정할 근거가 부족하다. 다음 최소 배치는 **TXT 계측과
  장식/줄바꿈 비교**이며, A396은 현재 TextBox를 유지하되 검색 모델과 UI 접근을 분리해 진행할 수 있다.

증거 표기의 의미: **코드 확인**은 소스 경로·조건을 확인했다는 뜻, **실측**은 아래 콘솔 모델 실행에
한정된다. **후보**는 아직 UI에서 비용을 확인하지 않은 가설이다. 기존 소스 주석의 “수 초”, “수백 ms”,
과거 A177/A343의 실기기 기록을 이번 장치·이번 입력의 실측으로 재사용하지 않는다.

### 두 상한의 정확한 의미

`MaxBytes = 4 * 1024 * 1024`(`DocumentView.xaml.cs:140`)는 디스크 바이트 제한이다.
`LargeDocumentChars = 1024 * 1024`(`:159`)는 **C# string.Length, UTF-16 코드 단위 수**이며
1MiB 파일 크기나 사용자 인식 글자 수가 아니다. BMP 한글은 UTF-8 3바이트지만 UTF-16 한 단위,
보조평면 문자는 서로게이트 두 단위다. 잘린 경계의 high surrogate는 한 단위 앞에서 끊는다(`:2589`).

| 원문 상태 | TXT 에디터 | 장식·기본 보기 |
|---|---|---|
| UTF-16 길이 1,048,575 또는 **1,048,576**, 4MiB 이하 | 전체 로드, 편집 가능 | `>` 비교이므로 자동 해제 안 됨. 토글·보기 상태에 따라 장식 실행 |
| 1,048,577 이상, 4MiB 이하 | 앞 1,048,576단위 이하, `_capped`, 읽기 전용 | 영구 장식 해제·2틱 지연 대입, Markdown 렌더/모드 토글 금지 |
| 4MiB 바이트 초과 | 앞 4MiB 디코드 뒤 문자 상한, `_truncated`도 설정 | TXT 앞부분만 표시. HTML은 에디터 비우고 원본 WebView2 표시. 인쇄/저장 제한 보존 |

**현 TXT는 전체 원문 읽기 전용 미리보기가 아니다.** 앞부분 미리보기임을 안내하는 계약이다.
향후 전체 원문 미리보기를 도입하면 별도 읽기 모델로 만들고, 편집 가능 범위와 분리해야 한다.
부분 버퍼를 전체 문서로 표시하거나 “모두 바꾸기” 뒤 원본에 저장하는 변경은 허용하지 않는다.

## 4. 재현 행렬과 이번 실행

먼저 표의 TXT 조합을 측정하고, 다른 형식은 동일 원문이 아닌 각 렌더러의 별도 대조군으로 둔다.
고정 조건은 창 콘텐츠 폭/높이 DIP, Windows 배율, 앱 배율, 본문 줌, 테마, 폰트, 보기/편집,
장식 두 토글, 정보/탐색 패널의 열림 상태다. 첫 열기와 충분히 안정된 뒤 스크롤을 별도 기록한다.

| 축 | 합성 입력/조작 | 이번 상태 |

## 6. A396에 제공할 검색 훅과 결정

1. **현재 TextBox를 유지한다.** 검색 엔진은 UI 비의존 모델로 만들고, DocumentView의 얇은 어댑터가
   `EditorText` 캐시(`:225`), selection, 범위 치환, 상태를 제공한다. 검색 때마다 `EditorBox.Text`를
   직접 읽거나 TextLineIndex를 새로 만드는 구현은 피한다.
2. 스냅샷은 `{text, documentGeneration, textRevision, completeness, canReplace}`처럼 명시한다.
   `documentGeneration`은 `_openSeq`/뷰 수명과 연계하고 textRevision은 TextChanged마다 증가시킨다.
   `DocumentSession`(`DocumentSession.cs:16`, `:30`)은 저장 세션이며 현재 검색용 revision이 없다.
   baseline이나 `_openSeq` 하나만으로 편집 중 오래된 검색 결과를 검증하지 않는다.
3. 검색 오프셋은 **현재 컨트롤 스냅샷의 UTF-16 인덱스**로 반환한다. baseline용 LF 정규화 문자열의
   위치를 그대로 Select에 넘기지 않는다. 개행 검색을 정규화한다면 위치 매핑도 함께 제공한다.
4. 찾기는 읽기 전용에서도 현재 제공되는 텍스트에 허용하고, capped/truncated면 결과 범위가
   **미리보기뿐**임을 알린다. 바꾸기는 전체 로드·편집 가능·현재 세대·비저장 충돌 상태에만 허용한다.
   `UpdateEditorReadOnly`(`DocumentView.xaml.cs:1562`), `SaveAsync` 가드, 더티 보호를 모두 보존한다.
5. 현재 결과로 이동은 SelectionStart/SelectionLength를 통해 어댑터에서 처리한다. 범위 치환은
   기존 탭 삽입의 `SelectedText` 선례(`DocumentView.xaml.cs:2859`)가 있으나, **모두 바꾸기의 undo
   단위는 별도 실기기 검증** 대상이다. 전문 Text 재대입이 undo/캐럿/더티를 보존한다고 가정하지 않는다.
6. worker에서 찾기/치환 결과를 계산하고 UI 반영 전 세대·revision을 검사한다. 결과 수 표시와
   이전/다음 탐색은 전체 텍스트 모델로, 강조는 현재 결과/보이는 범위만 예산 내에서 처리한다.
   **모든 일치에 GetRectFromCharacterIndex 호출 금지**. A401-a 계측을 검색 사용 전후에도 재사용한다.
7. Ctrl+F/Ctrl+H는 Document 및 All Readable의 현재 문서에 연결, Ctrl+C는 기존 복사 유지.
   키 반복·다른 입력 필드·탐색기 PassThroughTag·팝업 포커스는 기존 셸 규칙과 대조한다.
   이를 가상화 편집기와 직결된 검색 UI로 만들지 않는다.
